# 샬롬의 집 공식 홈페이지 콘텐츠 수집 및 공개 승인표

## 1. 문서 목적과 사용 원칙

이 문서는 홈페이지에 게시할 실제 정보를 시설 운영자와 홈페이지 담당자가 직접 작성하고, 사실과 공개 범위를 확인하고, 개인정보를 검수하고, 최종 승인하기 위한 내부 작업 문서다. 개발자가 승인된 정보만 전달받고 향후 변경 사항을 정기적으로 점검하는 기준으로도 사용한다.

- 확인되지 않은 정보는 홈페이지에 반영하지 않는다.
- `미작성`과 `비공개 결정`을 구분한다.
- `공개 승인` 전에는 입력 내용을 페이지 문구로 사용하지 않는다.
- 개인정보와 민감정보 원본을 이 문서에 붙여 넣지 않는다.
- 내부 문서 전체를 첨부하거나 복사하지 않는다. 확인 근거만 간단히 적는다.
- 법률·세무·후원 관련 전문 판단은 필요할 때 별도로 확인한다. 이 문서는 법률 자문이 아니다.
- 정보가 변경되면 승인 상태, 갱신일과 다음 검토일을 함께 수정한다.
- 개발자는 상태가 `공개 승인`인 값만 구현 대상으로 사용한다.

> 이 문서에는 주민등록번호, 진단명, 의료기록, 개인 연락처, 보호자 정보,
> 비공개 후원자 정보, 계정 비밀번호, 내부 사건 기록 및 미승인 문서를
> 입력하지 않습니다.

이 문서는 공개 홈페이지, 시설 홍보문 초안, 개인정보 원본 보관 문서, 직원 인사자료, 거주인 기록, 후원자·자원봉사자 명단, CMS·DB 스키마, 실제 신청서 또는 실제 동의서 양식이 아니다.

## 2. 상태값 정의

문서 전체에서는 다음 상태만 사용하며 상태 이름을 임의로 추가하지 않는다.

| 상태          | 의미                                         |
| ------------- | -------------------------------------------- |
| `미작성`      | 아직 내용을 받지 못함                        |
| `확인 중`     | 사실관계 또는 공개 범위를 확인 중            |
| `확인 완료`   | 사실은 확인됐지만 공개 승인은 아직 받지 않음 |
| `공개 승인`   | 홈페이지 공개와 개발 반영이 승인됨           |
| `비공개 결정` | 공식적으로 홈페이지에 공개하지 않기로 결정   |
| `보류`        | 운영 방식 또는 전문 검토가 끝날 때까지 중단  |

`확인 완료`와 `공개 승인`은 같은 의미가 아니다. 사실 확인 뒤에도 최종 공개 승인을 별도로 받아야 한다.

## 3. 역할과 책임

| 역할                 | 담당자 또는 직책 | 책임                             | 현재 확정 여부 |
| -------------------- | ---------------- | -------------------------------- | -------------- |
| 콘텐츠 작성자        | `[운영자 입력]`  | 원문 작성과 자료 제공            | `미작성`       |
| 사실 확인자          | `[운영자 입력]`  | 시설 정보와 사실관계 확인        | `미작성`       |
| 개인정보 검수자      | `[운영자 입력]`  | 개인정보·민감정보 포함 여부 확인 | `미작성`       |
| 최종 승인자          | `[운영자 입력]`  | 홈페이지 공개 최종 승인          | `미작성`       |
| 홈페이지 반영 담당자 | `[운영자 입력]`  | 승인된 내용의 개발 반영          | `미작성`       |
| 정기 검토 담당자     | `[운영자 입력]`  | 오래된 정보와 변경사항 점검      | `미작성`       |

실제 사람 이름을 추측해서 쓰지 않는다. 개발자의 가족관계나 개인적 인연도 기록하지 않는다. 이름 공개가 필요하지 않으면 담당 직책만 기록할 수 있다.

## 4. 모든 콘텐츠에 공통으로 기록할 항목

각 콘텐츠 수집표에는 가능한 범위에서 다음 열을 사용한다. 아래 빈 행을 복사해 항목별로 작성한다.

| 항목            | 현재 표시값 또는 입력 내용 | 상태     | 확인 근거       | 공개 범위       | 최종 승인자     | 승인일          | 갱신 담당자     | 다음 검토일     | 비고            |
| --------------- | -------------------------- | -------- | --------------- | --------------- | --------------- | --------------- | --------------- | --------------- | --------------- |
| `[운영자 입력]` | `[운영자 입력]`            | `미작성` | `[운영자 입력]` | `[운영자 입력]` | `[운영자 입력]` | `[운영자 입력]` | `[운영자 입력]` | `[운영자 입력]` | `[운영자 입력]` |

- 현재 값이 코드에 있으면 공식 정보가 아니라 `현재 표시값`으로만 기록한다.
- 공식 확인 전에는 상태를 `공개 승인`으로 바꾸지 않는다.
- 확인 근거에는 문서명·공식 기록·운영자 확인 방식만 기록하고, 내부 문서의 개인정보나 전체 내용은 복사하지 않는다.
- 승인일은 실제 승인 후 입력하며 날짜는 `YYYY-MM-DD` 형식을 사용한다.
- 담당자 이름 공개가 불필요하면 내부 직책만 기록할 수 있다.

## 6. 홈페이지 `/`

홈페이지에 필요한 최소 콘텐츠를 수집한다.

| 항목                               | 입력 내용                 |
| ---------------------------------- | ------------------------- |
| 홈페이지 대표 한 문장              | `[운영자 입력]`           |
| 시설을 소개하는 짧은 문단          | `[운영자 입력 — 2~4문장]` |
| 홈페이지에서 가장 먼저 안내할 정보 | `[운영자 입력]`           |
| 방문자가 우선 확인해야 할 경로     | `[운영자 입력]`           |
| 홈페이지에 대표 사진을 사용할지    | `[운영자 입력]`           |
| 대표 사진 공개 승인 상태           | `[운영자 입력]`           |

감정적인 홍보 문구, 확인되지 않은 성과 수치, 거주인의 어려움을 강조한 모금 문구, 실제 운영과 다른 슬로건, 이용자 수·후원금·프로그램 수의 추정값은 요구하거나 작성하지 않는다.

## 7. 시설 소개 `/about`

### 기본 소개

다음 항목마다 4절의 공통 수집표를 사용한다.

- 공식 시설 소개 문구
- 설립 목적
- 운영 철학 또는 운영 방향
- 공식 미션·비전 존재 여부
- 시설의 법적·행정적 명칭 공개 범위
- 설립일 또는 개원일
- 운영 주체
- 시설의 주요 역할
- 지역사회와의 관계를 설명할 공식 문구

### 연혁

| 날짜 또는 연도  | 공식 사건명     | 공개 가능한 설명 | 확인 근거       | 상태     |
| --------------- | --------------- | ---------------- | --------------- | -------- |
| `[운영자 입력]` | `[운영자 입력]` | `[운영자 입력]`  | `[운영자 입력]` | `미작성` |

가짜 연혁을 만들지 않는다. 정확한 날짜를 확인하지 못하고 연도만 확인됐다면 연도만 기록한다.

### 조직과 직원

- 조직도 공개 여부
- 부서명 공개 범위
- 원장 이름 공개 여부
- 사무국장 등 직책 공개 여부
- 직원 실명 공개 범위
- 업무용 연락처 공개 범위
- 퇴사·보직 변경 시 갱신 담당자

직원의 개인 전화번호와 개인 이메일은 입력하지 않는다.

### 시설 환경과 방문 정보

- 공개 가능한 시설 공간
- 시설 사진 공개 가능 여부
- 정확한 방문 안내
- 대중교통 안내
- 주차 안내
- 방문 전 연락 필요 여부
- 방문 가능 시간 공개 여부
- 건물 접근 편의 정보
- 지도 서비스 연결 여부

실제 운영 또는 보안상 공개하면 안 되는 출입 정보는 기록하지 않는다.

## 8. 함께하는 생활 `/life`

다음 네 범위를 구분해 작성한다.

```text
생활 안내
주요 프로그램
활동 이야기
시설 이용 관련 안내
```

### 프로그램 정보 수집표

| 항목                          | 입력 내용       |
| ----------------------------- | --------------- |
| 공식 프로그램명               | `[운영자 입력]` |
| 프로그램 목적                 | `[운영자 입력]` |
| 공개 가능한 대상 설명         | `[운영자 입력]` |
| 공개 가능한 활동 내용         | `[운영자 입력]` |
| 일정 공개 여부                | `[운영자 입력]` |
| 담당 부서 또는 직책 공개 여부 | `[운영자 입력]` |
| 사진 사용 여부                | `[운영자 입력]` |
| 개인정보 검수 상태            | `[운영자 입력]` |
| 최종 공개 상태                | `[운영자 입력]` |

프로그램마다 위 표를 복사해 사용한다. 개인별 장애 특성, 건강 상태, 상담 내용, 개별 지원계획, 보호자 정보, 특정 거주인의 상세 생활기록, 정확한 실시간 동선이나 안전상 민감한 일정은 입력하지 않는다.

### 활동 이야기

다음 항목마다 4절의 공통 수집표를 사용한다.

- 활동명
- 활동 날짜 공개 여부
- 공개 가능한 활동 설명
- 참여자 식별 가능 여부
- 사람 이름 공개 여부
- 사진 공개 동의 확인
- 배경 개인정보 확인
- 대체 텍스트 초안
- 게시 종료일 또는 재검토일

## 13. 공개 금지 정보 점검표

- [ ] 주민등록번호가 포함되지 않았다.
- [ ] 진단명·의료기록·복약 정보가 포함되지 않았다.
- [ ] 상담 기록과 개별 지원계획이 포함되지 않았다.
- [ ] 보호자 개인정보와 가족관계 정보가 포함되지 않았다.
- [ ] 거주인 개인 연락처가 포함되지 않았다.
- [ ] 직원 개인 연락처와 개인 이메일이 포함되지 않았다.
- [ ] 비공개 후원자 정보가 포함되지 않았다.
- [ ] 내부 인사자료가 포함되지 않았다.
- [ ] 내부 사건·사고 기록이 포함되지 않았다.
- [ ] 내부 회의록이 포함되지 않았다.
- [ ] 미승인 예산·결산 자료가 포함되지 않았다.
- [ ] 개인정보가 포함된 신청서 원본이 포함되지 않았다.
- [ ] 계정 비밀번호와 인증정보가 포함되지 않았다.
- [ ] 여러 정보를 결합해 개인을 추정할 가능성을 검토했다.

이 점검은 기본적인 공개 전 확인이며 법률 검토 완료를 의미하지 않는다. 전문 판단이 필요한 내용은 별도로 검토한다.

## 15. 운영자에게 전달할 1차 질문

8. 조직도와 직원 이름·직책을 어느 범위까지 공개할 수 있습니까?

11. 방문·입소·시설 이용 안내를 홈페이지에 공개합니까?
12. 공식 후원 방법은 무엇입니까?

답변하지 않은 항목은 자동으로 승인된 것으로 처리하지 않는다.

## 16. 개발자 전달 패키지

운영자의 답변을 개발자가 사용할 때 다음 자료를 하나의 전달 단위로 준비한다.

```text
1. 공개 승인된 문구
2. 항목별 승인 상태
3. 사실 확인 근거
4. 최종 승인자 또는 승인 직책
5. 승인일
6. 사용할 공개용 이미지
7. 이미지별 동의 및 검수 상태
8. 사용할 공개용 첨부파일
9. 페이지별 반영 위치
10. 다음 검토일
```

다음 자료는 전달 패키지에 포함하지 않는다.

```text
내부 문서 원본
개인정보 원본
동의서 원본
직원 개인 연락처
후원자 명단
신청서 원본
비밀번호
관리자 인증정보
```

## 17. 실제 콘텐츠 구현 시작 조건

다음 조건을 모두 만족한 항목만 페이지에 반영한다.

```text
상태가 공개 승인
사실 확인 근거 존재
공개 범위 명확
개인정보 검수 완료
최종 승인자 확인
실제 문구 또는 파일 확보
반영 대상 페이지 확정
```

일부 조건이 비어 있으면 구현하지 않고 확인이 필요한 항목으로 유지한다. 개발자가 문구를 임의로 완성하거나 사실을 보충하지 않는다.
