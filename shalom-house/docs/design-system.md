# 디자인 시스템 — V5 · 구조 개편

## 방향

샬롬의 집은 생활·공간·활동 기록을 편하게 살펴볼 수 있는 작은 기관 홈페이지다. 따뜻한 백색과 짙은 녹색, 여백과 사진으로 인상을 만들며 공문형 상단선과 동일한 카드 반복을 줄인다. 기관명과 실제 CMS 문구를 사용하고 새 슬로건이나 기관 정보를 만들어 넣지 않는다.

사용자 지시로 공개 랜딩·목록·상세와 관리자 화면을 함께 개편한다. 기존 V3/V4의 화면 배치 규정은 이 문서로 대체한다. 콘텐츠 공개 조건·이름 공개 동의·접근 제어·날짜·검색 복귀 정책은 유지한다.

## 참고와 적용

- 사랑의열매: 참여 행동을 명확히 구분하는 탐색과 주 행동의 색 대비를 참고한다. 모금 입력창·자동 슬라이드·팝업·그라디언트는 가져오지 않는다.
- 초록우산: 사용자 지정 참고 대상이다. 화면 접근이 확인되지 않은 디자인을 실제 관찰 근거로 기록하지 않는다.
- 대학 홈페이지: 연세대학교의 기관 소개·기록·방문 목적별 정보 분리 방식을 참고한다. 대학의 메뉴 규모나 기관 문구를 복제하지 않는다.
- 도깨비테니스: 공개 영역의 브랜드 표현과 관리자 업무 영역의 강도를 구분하고, 버튼 역할·현재 위치·반응형 탐색을 일관되게 적용하는 원칙을 참고한다. 블랙·라임의 스포츠 표현을 복제하지 않는다.

## 토큰

실제 값의 단일 출처는 `src/app/globals.css`다. 컴포넌트 안에 색상 값을 추가하지 않는다.

| 역할         | 토큰                             | 사용                                        |
| ------------ | -------------------------------- | ------------------------------------------- |
| 본문         | foreground / muted-foreground    | 짙은 중립색 / 보조 설명                     |
| 기관·주 행동 | primary / primary-hover          | 짙은 녹색, 핵심 링크·버튼·푸터              |
| 보조 강조    | accent / accent-soft             | 분류·포커스·선택 관련 정보                  |
| 배경         | surface / surface-subtle / paper | 백색 / 옅은 중립 / 따뜻한 종이색            |
| 참여 강조    | brand-highlight                  | 홈 참여 영역 한 곳의 연한 연두색            |
| 상태         | success / warning / danger       | 업무 상태 의미. 브랜드색과 혼동하지 않는다. |

Pretendard Variable을 로컬로 제공한다. 큰 제목은 650~~750, 소제목은 600~~700, 본문은 400~~500을 기준으로 한다. 홈 기관명은 유동 크기, 내부 제목은 32~~48px, 주요 랜딩은 최대 64px, 본문은 16~18px다. 길이가 긴 제목은 잘라내지 않는다.

## 구성

- 홈은 큰 기관명, 생활사진, 기관 설명과 빠른 안내로 시작하는 표지다. 최근 소식을 바로 다음에 배치한다. 같은 폭의 9개 구획을 순서대로 쌓지 않는다.
- 생활사진은 가로로 탐색하는 기록, 프로그램은 펼쳐 읽는 목록, 기관 정보는 좌우 분할, 참여 안내는 큰 링크, 문서·연락처는 하나의 마지막 구획으로 구성한다.
- 내부 페이지는 왼쪽 제목·세부 탐색과 오른쪽 콘텐츠 캔버스로 나눈다. 상단 대형 제목 + 가로 탭을 전 페이지에 반복하지 않는다. 767px 이하에서는 세로로 쌓고 탐색을 줄바꿈한다.
- 소식·프로그램·갤러리 상세는 목록 복귀·분류·날짜를 왼쪽 읽기 보조 영역, 제목·본문·사진을 오른쪽 읽기 영역에 둔다.
- 콘텐츠를 담은 상자 대신 구분선, 폭 차이, 사진 크기와 흐름으로 구획을 표현한다. 새 기관 문구나 가짜 통계로 화면을 채우지 않는다.

## 인터랙션

- 사진 탐색은 이전/다음 버튼으로만 동작한다. 자동재생·시차 스크롤·커서 추적은 사용하지 않는다.
- 캐러셀은 현재 사진의 제목과 순서를 알리고, 버튼 포커스를 유지한다. 실패한 사진에도 설명과 목록 경로를 제공한다.
- 메뉴는 클릭, 키보드, Escape, 외부 클릭으로 동작한다. 기존 포커스 복귀와 경로 변경 시 닫기를 유지한다.
- 사진 hover는 최대 1.025배, 버튼 이동은 2px 수준이다. 모션은 150~400ms를 기본으로 하며 본문을 화면 밖에서 숨겨 대기시키지 않는다.
- `prefers-reduced-motion`에서는 움직임을 제거한다. 모든 버튼·링크는 모션 없이도 상태를 이해할 수 있어야 한다.
- 포커스는 2px outline과 양수 offset이 기본이다. 이미지 클리핑과 키보드 포커스를 함께 점검한다.

## 관리자

- 왼쪽 업무군 레일(업무 홈/콘텐츠/운영/관리)과 상단의 해당 업무 메뉴, 넓은 작업 캔버스를 사용한다. 각 메뉴는 기존 권한 그대로 노출한다.
- 대시보드: 콘텐츠별 목록·새 작성 동작을 한 줄씩 제공하고 운영 업무를 별도 영역으로 구분한다. 추측한 업무 건수는 표시하지 않는다.
- 목록: 전체 폭 헤더 아래 왼쪽 필터, 오른쪽 결과. 작은 화면에서는 필터 다음 결과가 온다.
- 상세: 제목·수정 행동 아래 내용과 상태 보조 영역을 분리한다. 게시·동의·삭제 관련 안내와 확인은 숨기지 않는다.
- 편집: 왼쪽 작업 설명·복귀, 오른쪽 폼. 작은 화면에서는 설명 다음 폼이 온다.
- 모바일에서는 업무군 레일이 상단 탐색으로 바뀐다. 저장·인증·검증·권한·감사 로직은 변경하지 않는다.

## 디자인 검토 화면

`/design-preview`와 `/design-preview/admin`은 development/preview 환경에서만 렌더링하고 production은 404다. 공개 홈과 관리자 셸·헤더·필터·상태 등의 실제 컴포넌트를 테스트 데이터로 검토한다. 실제 관리자 세션이나 저장소를 조회하지 않으며 저장·게시·삭제 기능은 없다. 기관 사진이 아닌 샘플 이미지는 명시한다. 이 화면의 확인을 실제 관리자 기능 검증으로 보고하지 않는다.

## 확인 기준

기능·접근성·시각 판단은 별도 기록한다. 실제로 보지 못한 viewport나 인증 화면을 PASS로 기록하지 않는다. 새로운 테스트 데이터·스톡 인물·허구의 기관 문구로 부족한 화면을 채우지 않는다.
