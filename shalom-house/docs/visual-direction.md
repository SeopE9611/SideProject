# 샬롬의 집 시각 디자인 방향 및 레퍼런스 원칙

## 1. 문서 목적

이 문서는 현재 정보구조와 접근성 기반 위에 시각적 완성도를 높이기 위한 장기 기준이다. 레퍼런스를 복제하지 않고 사용자 목적과 콘텐츠 구조에 맞는 패턴만 추출하며, 공식 CI와 사진이 없어도 유지 가능한 시각 구조를 정의한다. 실제 자료가 확보되면 구조를 깨지 않고 콘텐츠를 연결할 수 있도록 설계한다.

고령자와 디지털 사용이 익숙하지 않은 방문자를 우선 고려하고, 장애인의 다양한 웹 이용 방식을 제한하지 않는 디자인을 지향한다. 샬롬의 집 홈페이지는 감정적 모금 중심 사이트가 아니라 시설 정보와 참여 정보를 신뢰성 있게 제공하는 사이트여야 한다.

이 문서는 공식 브랜드 가이드나 CI 확정을 대신하지 않으며, 현재 구현을 최종 디자인으로 선언하지 않는다.

## 2. 현재 UI 진단

현재 구조는 정보구조와 접근성을 먼저 세운 의도적인 기반 작업이며, 안정적인 1차 UI 위에 후속 시각 고도화가 필요한 상태다.

### 유지할 장점

- 의미 기반 색상 토큰
- 높은 기본 텍스트 대비
- 일관된 컨테이너와 여백
- 명확한 제목 계층
- 키보드 포커스
- 모바일 내비게이션
- 본문 바로가기
- Server Component 중심 구조
- 미확정 콘텐츠를 가짜 데이터로 채우지 않는 정책
- 승인된 사진이 없을 때도 작동하는 텍스트 기반 구조

### 개선이 필요한 부분

- 하위 페이지 대부분이 `좌측 소개 + 우측 안내 카드` 히어로를 반복한다.
- 여러 페이지가 원칙 카드 3개와 관련 링크 카드 구조를 반복한다.
- 카드가 정보의 종류와 관계없이 주된 표현 수단으로 사용된다.
- 페이지 목적이 달라도 제목·카드·배경 배치가 유사하다.
- 실제 콘텐츠보다 “준비 중”과 정책 설명이 시각적으로 큰 비중을 차지한다.
- 페이지 사이의 리듬과 정보 밀도 차이가 작다.
- 텍스트 위주 상태에서 시선이 머무를 중심 요소가 부족하다.
- 관련 페이지 링크가 여러 페이지에서 반복돼 사이트가 길고 유사하게 느껴질 수 있다.
- `/support` 강조가 모든 페이지에서 반복되면 과도한 참여 요청으로 인식될 수 있다.
- 현재 UI는 안정적인 1차 구조지만 최종 브랜드 경험은 아니다.

## 3. 디자인 목표

핵심 콘셉트는 **따뜻한 일상, 명확한 안내**다.

### 평온함

- 과도한 색상과 장식 없이 안정적인 화면을 만든다.
- 넉넉한 여백과 읽기 쉬운 문장 폭을 유지한다.
- 빠르게 움직이는 요소를 사용하지 않는다.

### 환대

- 시설을 처음 방문한 사람도 다음 행동을 이해할 수 있게 안내한다.
- 차갑고 행정적인 문서 화면만으로 구성하지 않는다.
- 감정적 압박이 아닌 정중하고 친절한 문구를 사용한다.

### 신뢰

- 확인된 정보와 미확정 정보를 명확히 구분한다.
- 날짜·분류·파일 정보 등 필요한 메타데이터를 숨기지 않는다.
- 실제 운영자료와 연락처를 찾기 쉽게 구성한다.

### 존엄

- 거주인을 모금이나 홍보를 위한 대상으로 표현하지 않는다.
- 불쌍함·극복 서사·과도한 감정 자극을 디자인 전략으로 사용하지 않는다.
- 사진과 이야기는 당사자의 존엄·동의·맥락을 우선한다.

### 명료함

- 한 화면에서 주요 목적이 하나 또는 소수로 드러나게 한다.
- 링크와 버튼의 우선순위를 명확히 한다.
- 카드·색상·아이콘보다 제목과 문장 구조를 우선한다.

### 접근성

- 확대와 reflow를 방해하는 장식을 금지한다.
- 키보드 포커스가 분명한 상호작용을 제공한다.
- 색상만으로 상태와 현재 위치를 전달하지 않는다.
- 불필요한 자동 재생과 애니메이션을 금지한다.

## 4. 레퍼런스 사용 원칙

- 레퍼런스 사이트의 고유 문구, 이미지, 로고, 색상, 코드와 레이아웃을 복제하지 않는다.
- 방문자 목적과 정보 유형에 맞는 구조적 패턴만 분석한다.
- 대형 재단의 모금 캠페인 구조를 소규모 거주시설에 그대로 적용하지 않는다.
- 공공기관의 복잡한 정보 밀도를 메인 페이지에 그대로 적용하지 않는다.
- 접근성 도구가 존재한다는 이유로 동일한 도구 모음을 무조건 구현하지 않는다.
- 실제 기능과 콘텐츠가 없는 인터랙션을 장식 목적으로 만들지 않는다.
- 레퍼런스는 방향 결정 근거이며 디자인 결과물 자체가 아니다.
- 시각적 세부사항은 향후 실제 화면 비교와 공식 콘텐츠 확보 후 확정한다.

## 5. 레퍼런스 분석

### NULI

**참고 범위**

- 본문 바로가기
- 접근성 기능을 쉽게 찾을 수 있는 구조
- 명확한 주요 메뉴
- 접근성을 기획·디자인·마크업·개발 전체의 책임으로 다루는 방식

**샬롬의 집 적용 방향**

- 접근성 기능을 숨은 기술 요구가 아니라 가시적인 사용성 기준으로 관리한다.
- 쉬운 탐색과 분명한 포커스를 유지한다.
- 확대·색상·읽기 보조 기능은 실제 필요성과 구현 품질을 검토한 후 도입한다.
- 별도 접근성 도구가 기본 HTML과 브라우저 기능을 방해하지 않도록 한다.

**적용하지 않을 내용**

- 기능 필요성 검토 없이 접근성 도구 모음을 그대로 복제하지 않는다.
- 도구 버튼이 많다는 이유만으로 접근성이 확보됐다고 판단하지 않는다.

### 밀알복지재단

**참고 범위**

- 주요 행동의 명확한 우선순위
- 이야기·소식·후원 안내의 구획
- 최신 소식과 FAQ를 메인 흐름에서 찾기 쉽게 배치하는 구조
- 기관 활동을 실제 콘텐츠로 보여주는 방식

**샬롬의 집 적용 방향**

- 실제 콘텐츠 확보 후 메인에서 최근 소식과 생활 이야기의 일부를 제공한다.
- 중요한 참여 경로에는 분명한 CTA를 제공한다.
- 페이지마다 목적에 맞는 정보 밀도와 시각 중심을 설정한다.

**적용하지 않을 내용**

- 감정적으로 강한 모금 캠페인 중심 히어로
- 거주인의 어려움이나 장애를 후원 전환 장치로 사용하는 방식
- 자동 순환 캠페인 배너
- 모든 화면에서 반복되는 강한 후원 요청
- 실제 운영 기능이 없는 후원 CTA

### 사랑의열매

**참고 범위**

- 운영 정보와 공시자료의 체계적인 분류
- 표와 다운로드 자료의 제목·기간·형식 구분
- 작성·확인 책임과 자료 기준의 명시
- 투명성 정보를 독립적인 정보 영역으로 관리하는 방식

**샬롬의 집 적용 방향**

- 실제 운영자료가 확보되면 자료 제목, 분류, 기준 기간, 게시일, 파일 형식과 용량을 표시한다.
- 공개자료를 일반 홍보 카드와 다른 문서 목록 형태로 제공한다.
- 자료의 공개 승인과 개인정보 검수 상태를 운영 정책에서 관리한다.

**적용하지 않을 내용**

- 현재 자료가 없는 상태에서 복잡한 표와 분류를 생성하지 않는다.
- 대형 기관의 정보량을 그대로 복제하지 않는다.
- 확인되지 않은 담당자·감독자·법적 공시 정보를 생성하지 않는다.

### 한국장애인개발원

**참고 범위**

- 공지와 연구자료 목록의 분류·제목·날짜·첨부 여부
- 사용자가 자료 성격을 목록 단계에서 판단할 수 있는 메타데이터
- 검색과 분류가 필요한 대량 콘텐츠 구조

**샬롬의 집 적용 방향**

- 실제 게시물이 생기면 소식 목록에 분류·제목·게시일을 제공한다.
- 운영자료 목록에 자료 종류·기준 기간·파일 정보를 제공한다.
- 데이터가 충분히 쌓인 이후에만 검색·분류 기능을 검토한다.

**적용하지 않을 내용**

- 모바일에서 읽기 어려운 고밀도 데스크톱 표
- 데이터가 적은 상태에서 불필요한 검색·필터
- 조회수처럼 운영 목적이 불명확한 메타데이터

## 6. 전역 시각 언어

### 색상

- 현재 의미 토큰 체계를 유지한다.
- 공식 CI 확정 전 새 브랜드 색상을 임의로 추가하지 않는다.
- `primary`는 주요 행동과 현재 위치에 사용한다.
- `accent`는 매우 제한적인 따뜻한 강조에만 사용한다.
- 한 화면에 강한 색상 면을 반복하지 않는다.
- 배경색 교차는 섹션 구분이 필요한 경우에만 사용한다.
- 텍스트 위에 불투명도가 낮은 장식 배경을 겹치지 않는다.
- 상태는 색상 외 텍스트·레이블·형태를 병행한다.

### 타이포그래피

- 현재 시스템 폰트와 의미 기반 글자 크기를 유지한다.
- 공식 폰트가 확인되기 전 외부 웹폰트를 추가하지 않는다.
- 큰 제목을 모든 섹션에서 반복하지 않는다.
- 본문은 읽기 폭을 제한하고 충분한 행간을 유지한다.
- 긴 한국어 문장을 짧은 문단으로 분리한다.
- 작은 글자를 주요 정보 전달에 사용하지 않는다.
- 영문 대문자와 과도한 자간을 장식 목적으로 사용하지 않는다.

### 여백과 리듬

- 모든 내용을 카드에 넣지 않는다.
- 문서형 내용은 제목·문단·구분선으로 표현한다.
- 카드가 필요한 독립 정보와 일반 본문을 구분한다.
- 섹션마다 같은 `py`, 같은 배경, 같은 카드 그리드를 기계적으로 반복하지 않는다.
- 화면의 시작·중간·끝에 시각적 리듬 차이를 제공한다.
- 모바일에서는 여백을 줄이되 요소가 붙어 보이지 않도록 유지한다.

### 모서리와 그림자

- 모든 영역에 `rounded-card`와 `shadow-card`를 적용하지 않는다.
- 그림자는 실제로 떠 있는 상호작용 표면이나 핵심 안내에 제한한다.
- 문서 목록과 일반 콘텐츠는 선·간격·배경 변화로 구분한다.
- 같은 화면에서 카드 모서리와 그림자 강도를 일관되게 사용한다.

### 아이콘

- 기능과 의미를 보완할 때만 사용한다.
- 아이콘만으로 링크나 상태를 전달하지 않는다.
- 장식 아이콘을 카드마다 반복하지 않는다.
- 새 아이콘 패키지는 별도 검토 없이 추가하지 않는다.
- 텍스트 화살표도 실제 이동 의미가 있을 때만 사용한다.

## 7. 인터랙션 원칙

### 허용하는 인터랙션

- 링크와 버튼의 명확한 hover·focus·active 상태
- 모바일 내비게이션 disclosure
- 실제로 긴 콘텐츠가 생겼을 때의 접근 가능한 아코디언
- 실제 데이터가 충분할 때의 검색·분류·페이지 이동
- 상태 변화가 있는 기능의 명확한 성공·오류 피드백
- 정보 이해를 방해하지 않는 짧은 색상·위치 전환
- `prefers-reduced-motion` 적용

### 지양하는 인터랙션

- 자동 순환 슬라이드
- 자동 재생 영상·음성
- 장식 목적의 패럴랙스
- 스크롤에 따라 계속 나타나는 요소
- 카드가 떠오르거나 흔들리는 과도한 hover
- 배경 영상
- 의미 없는 숫자 카운터 애니메이션
- 클릭할 수 없는 요소에 hover 효과
- 실제 기능이 없는 탭·필터·드롭다운
- 키보드와 터치에서 결과가 다른 기능

### 모션 기준

- 현재 `150ms`, `200ms` 토큰 범위를 유지한다.
- 색상과 작은 위치 변화만 기본 허용한다.
- 콘텐츠 등장 애니메이션을 전역 기본값으로 사용하지 않는다.
- 움직임을 제거해도 정보와 기능이 완전히 유지돼야 한다.

## 8. CTA와 참여 요청 원칙

- 한 섹션의 주요 CTA는 원칙적으로 하나다.
- 보조 행동은 시각적 위계를 낮춘다.
- `/support`를 모든 페이지에서 강한 색상 카드로 반복하지 않는다.
- 후원과 봉사 요청은 실제 방법이 확정된 후에만 행동형 CTA로 제공한다.
- 미확정 상태에서는 안내 페이지 이동 수준으로 제한한다.
- 감정적 압박, 긴급성 조작, 죄책감 유발 문구를 사용하지 않는다.
- 버튼 문구는 이동 또는 동작 결과를 예측할 수 있게 작성한다.
- 같은 목적의 CTA를 한 화면에 중복 배치하지 않는다.
- 전화 링크는 용도를 정확히 설명한다.
- 일반 정보 탐색과 참여 요청이 경쟁하지 않도록 구성한다.

## 9. 카드 사용 분류

향후 다음 유형을 구분하되, 이번 문서 작업에서 컴포넌트나 타입을 구현하지 않는다.

### 내비게이션 카드

- 사용자가 다른 페이지로 이동하는 명확한 목적이 있어야 한다.
- 제목·설명·이동 문구를 제공한다.
- 카드 전체가 링크인 경우 중첩 상호작용을 금지한다.

### 핵심 안내 카드

- 대표 전화, 주소, 참여 상태 등 중요한 독립 정보에 사용한다.
- 한 화면에 소수만 사용한다.
- 그림자는 필요성이 있을 때만 사용한다.

### 원칙·설명 블록

- 기본적으로 카드보다 문서형 열, 구분선 또는 번호 구조를 우선한다.
- 모든 원칙을 동일 카드 3개로 표현하지 않는다.

### 빈 상태

- 오류가 아닌 정상 상태를 분명하게 설명한다.
- 다음 행동은 한두 개만 제공한다.
- 장식 그림으로 빈 공간을 채우지 않는다.

### 소식 목록

- 제목·분류·게시일을 중심으로 구성한다.
- 실제 게시물이 생기면 카드보다 목록 구조를 우선 검토한다.
- 썸네일은 필수가 아니다.

### 운영자료 목록

- 자료 제목·분류·기준 기간·게시일·파일 정보를 중심으로 구성한다.
- 일반 홍보 카드와 명확히 다른 문서형 구조를 사용한다.

이 분류는 UI 방향이며 현재 범용 컴포넌트가 구현됐다는 의미가 아니다.

## 10. 이미지와 사진 방향

- 실제 시설과 활동을 보여주는 승인된 사진을 우선한다.
- 스톡 사진으로 실제 시설처럼 오인하게 하지 않는다.
- AI 생성 인물 사진을 실제 거주인·직원처럼 사용하지 않는다.
- 거주인의 존엄과 사생활을 우선한다.
- 촬영·공개 동의와 배경 개인정보를 검수한다.
- 이름, 위치, 일정, 건강·장애 정보의 조합으로 개인을 식별할 가능성을 검토한다.
- 불쌍함, 고립, 고통을 강조하는 구도를 지양한다.
- 일상, 관계, 환경, 활동의 맥락을 균형 있게 전달한다.
- 정보 이미지에는 목적에 맞는 대체 텍스트를 제공한다.
- 장식 이미지는 빈 대체 텍스트를 사용하거나 적절히 보조기술에서 제외한다.
- 이미지 안의 글자를 주요 정보 전달 수단으로 사용하지 않는다.
- 텍스트를 사진 위에 배치할 때 실제 대비를 검증한다.
- 승인된 이미지가 없으면 현재 텍스트 기반 디자인을 유지한다.

## 11. 페이지별 시각 방향

### 홈 `/`

**역할: 사이트 전체의 안내 허브**

- 모금 캠페인보다 시설 정보 탐색을 우선한다.
- 히어로에서 사이트 정체성과 핵심 이동 경로를 명확히 제공한다.
- 현재 5개 메뉴를 모두 같은 크기의 카드로 강조하지 않는다.
- 방문자의 주요 목적을 3개 안팎의 우선 흐름으로 재구성하는 방안을 검토한다.
- 주소와 전화는 별도 핵심 안내로 유지하되 히어로와 시각적 경쟁을 줄인다.
- 실제 게시물이 생기면 최근 소식 일부를 제공한다.
- 실제 승인 사진이 생기면 한 장의 대표 이미지 또는 절제된 이미지 영역을 검토한다.
- 자동 슬라이더를 사용하지 않는다.

### 시설 소개 `/about`

**역할: 시설의 정체성과 확인된 기본 정보 제공**

- 소개 문장과 기본 사실을 읽는 편집형 페이지로 구성한다.
- 모든 내용을 링크 카드로 만들지 않는다.
- 향후 연혁은 타임라인보다 먼저 읽기 쉬운 연도·내용 목록을 검토한다.
- 시설 환경 사진은 실제 승인 자료가 있을 때만 사용한다.
- 주소·대표 전화·방문 안내를 명확한 정보 블록으로 구성한다.
- 다른 페이지 링크는 소수만 제공한다.

### 함께하는 생활 `/life`

**역할: 생활과 프로그램을 존중하는 방식으로 전달**

- 실제 콘텐츠가 생기면 사진과 짧은 설명이 결합된 이야기 구조를 검토한다.
- 프로그램을 동일 카드 반복보다 주제별 섹션으로 구분한다.
- 활동 사진만 나열하지 않고 맥락과 목적을 설명한다.
- 거주인을 홍보 모델로 다루지 않는다.
- 콘텐츠가 없는 현재는 정책 설명을 지나치게 많은 카드로 표현하지 않는다.

### 샬롬 소식 `/news`

**역할: 공지사항과 활동 소식 탐색**

- 실제 게시물이 생기면 목록을 페이지의 중심으로 전환한다.
- 큰 히어로의 비중을 줄이고 제목·분류·게시일을 우선한다.
- 공지사항과 활동 소식의 차이를 분류 레이블로 제공한다.
- 게시물 수가 적을 때 검색·필터를 만들지 않는다.
- 썸네일 없는 게시물도 완성된 목록으로 보여야 한다.
- 빈 상태는 간결하게 유지한다.

### 후원과 봉사 `/support`

**역할: 공식 참여 방법과 문의 경로 제공**

- 실제 방법이 확정되면 행동 단계와 준비 사항을 순서대로 안내한다.
- 후원과 봉사를 서로 다른 흐름으로 구분한다.
- 하나의 강한 CTA와 명확한 보조 문의를 제공한다.
- 감정적 캠페인 이미지와 압박성 문구를 사용하지 않는다.
- 대표 전화를 전용 접수 번호로 오인하게 하지 않는다.
- 신청 폼은 운영 방식과 개인정보 기준 확정 후 설계한다.

### 투명한 운영 `/transparency`

**역할: 승인된 운영자료 탐색**

- 실제 자료가 생기면 문서 목록을 페이지 중심으로 삼는다.
- 자료 제목·분류·기간·게시일·파일 형식·용량을 제공한다.
- 일반 카드보다 목록·구분선·메타데이터 구조를 우선한다.
- 자료가 적을 때 연도 필터와 검색을 만들지 않는다.
- 표가 필요한 경우 모바일 접근 방식을 별도로 설계한다.
- 빈 상태는 오류처럼 과도하게 강조하지 않는다.

### 404

**역할: 길을 잃은 방문자의 복귀 안내**

- 짧은 설명과 홈 이동을 제공한다.
- 장식보다 다음 행동을 우선한다.
- 존재하지 않는 검색·추천 기능을 추가하지 않는다.

## 12. 피해야 할 패턴

- 모든 페이지에서 동일한 2열 히어로 반복
- 모든 정보를 카드에 넣는 카드 중심 디자인
- 모든 섹션에서 같은 3열 카드 반복
- 모든 페이지 하단에 동일한 관련 링크 카드 반복
- 큰 제목을 여러 섹션에서 반복
- 공식 콘텐츠가 없다는 이유로 장식용 아이콘과 일러스트를 과도하게 추가
- 의미 없는 그라데이션과 배경 도형
- 자동 슬라이더와 캐러셀
- 텍스트가 이미지 위에서 읽히지 않는 구성
- 클릭할 수 없는 카드에 hover 효과
- 한 페이지에 여러 개의 강한 primary CTA
- 모금 전환을 위해 거주인의 장애와 어려움을 과장
- 불필요한 영문 슬로건
- 작은 보조 글자에 핵심 정보 배치
- 모바일에서 데스크톱 표를 그대로 축소
- 접근성 도구 버튼만 추가하고 기본 구조 문제를 방치
- 실제 데이터가 없는데 검색·필터·탭을 미리 구현

## 13. 콘텐츠 확보 단계별 전략

### 현재 단계

- 텍스트와 의미 토큰을 중심으로 구성한다.
- 미확정 정보를 가짜 콘텐츠로 채우지 않는다.
- 페이지 목적과 정보 계층을 먼저 고도화한다.
- 카드 사용을 줄이고 문서형 구조를 다양화한다.
- 사진을 전제로 고정 높이나 빈 프레임을 만들지 않는다.

### 공식 문구 확보 후

- 소개·연혁·운영 방향을 읽기 쉬운 편집형 구조로 연결한다.
- 기존 준비 문구를 실제 콘텐츠로 교체한다.
- 중복된 정책 설명을 운영 문서로 이동하거나 축소한다.

### 승인 사진 확보 후

- 페이지별 대표 이미지 필요성을 검토한다.
- 이미지 비율과 자르기 기준을 확정한다.
- 대체 텍스트와 캡션을 작성한다.
- 동의와 공개 범위를 기록한다.
- 이미지가 없어도 정보 접근이 가능하도록 유지한다.

### 실제 게시물과 운영자료 확보 후

- 소식 목록과 자료 목록 중심으로 페이지를 재구성한다.
- 데이터 수량을 확인한 뒤 검색·분류 필요성을 판단한다.
- 상세 라우트와 CMS는 별도 기능 설계 후 구현한다.

4. 공통 헤더·푸터의 시각 고도화
5. 홈 페이지 고도화
6. 시설 소개와 함께하는 생활 고도화
7. 샬롬 소식 고도화
8. 후원과 봉사 고도화
9. 투명한 운영 고도화
10. 실제 승인 콘텐츠와 이미지 연결
11. 전역 반응형·키보드·확대·스크린리더 재검증

### 구현 원칙

- 한 PR에서 전체 페이지를 동시에 재설계하지 않는다.
- 홈에서 패턴을 검증한 후 하위 페이지에 적용한다.
- 공통화는 실제 반복이 확인된 뒤 수행한다.
- 디자인 고도화와 CMS·DB 구현을 같은 PR에 섞지 않는다.
- 이미지 연결과 레이아웃 재설계를 무조건 한 번에 수행하지 않는다.
- 각 PR에서 접근성·반응형 검증 범위를 명확히 기록한다.

## 15. 디자인 고도화 완료 판단

- 페이지마다 목적에 맞는 정보 계층과 시각적 차이가 있다.
- 같은 카드와 섹션 패턴이 기계적으로 반복되지 않는다.
- 고령자와 디지털 사용이 익숙하지 않은 방문자가 주요 경로를 예측할 수 있다.
- 키보드·확대·reflow·동작 감소 환경에서 정보와 기능이 유지된다.
- 실제 콘텐츠가 없어도 가짜 정보 없이 완성된 빈 상태를 제공한다.
- 실제 콘텐츠가 들어와도 구조를 전면 교체하지 않아도 된다.
- 참여 CTA가 과도하거나 감정적으로 강요되지 않는다.
- 거주인의 존엄과 개인정보 원칙이 유지된다.
- 공식 CI와 사진이 확정되지 않은 부분은 미확정 상태로 유지한다.
- 전문 검증 전 접근성 적합 또는 인증을 마친 것으로 표현하지 않는다.

이 판단 기준은 후속 구현과 검증을 위한 기준이며, 현재 문서 작성만으로 디자인 고도화가 끝난 것은 아니다.
