# 샬롬의 집 시각 디자인 방향 및 레퍼런스 원칙

## 1. 문서 목적

이 문서는 샬롬의 집 홈페이지의 시각 언어와 콘텐츠 표현 기준을 다시 정의한다. 현재 메인·소개·생활 페이지의 화면과 문구를 발전시키는 문서가 아니라, 반복된 메시지와 유사한 페이지 구성을 교체하기 위한 기준이다.

## 2. 디자인 방향

샬롬의 집 홈페이지는 다음 인상을 목표로 한다.

- 집이 가진 편안함
- 공공 정보가 가진 명확함
- 실제 생활이 가진 자연스러움

감동을 요구하는 복지 캠페인 화면, 추상적인 가치 선언, 큰 숫자를 반복하는 기관 홍보 화면을 지향하지 않는다. 화면의 개성은 과장된 문구나 장식이 아니라 실제 사진, 콘텐츠 편집, 색상과 여백의 일관성에서 만든다.

## 3. 현재 구현 판단

### 유지

- Next.js App Router 구조
- 의미 기반 색상과 크기 토큰
- `max-w-site`, `max-w-content` 컨테이너 규격
- 키보드 포커스와 본문 바로가기
- 동작 감소 환경 지원
- 뉴스 데이터와 공개 콘텐츠 정책
- lint·typecheck·build CI

### 교체

- 현재 헤더와 상위 메뉴 구조
- 메인 히어로의 고정된 세 개 메시지
- 메인·소개·생활 페이지의 홍보 문구
- `30년+`, 지역명, 주소를 강조하는 통계와 정보 블록
- 페이지마다 반복되는 큰 감성 제목, 번호 목록, 관련 링크 목록
- 승인된 사진이 없다는 이유로 만든 추상적인 집·창문 그래픽

현재 화면은 최종 시각 레퍼런스로 사용하지 않는다.

## 4. 콘텐츠 우선순위

한 화면은 다음 순서로 설계한다.

1. 사용자가 이 페이지에서 확인할 정보
2. 실제 콘텐츠의 제목과 날짜 또는 상태
3. 다음 행동 또는 이동 경로
4. 필요한 경우에만 사진과 보조 설명

기관의 역사, 위치, 가치 문장을 빈 공간을 채우는 디자인 소재로 사용하지 않는다.

## 5. 문구 원칙

- 페이지마다 새로운 슬로건을 만들지 않는다.
- `존중`, `일상`, `함께`, `지역사회`를 의미 없이 반복하지 않는다.
- 감성적인 선언보다 시설이 실제로 제공하는 정보와 활동을 설명한다.
- 같은 소개 문장을 메인, 시설소개, 생활 페이지에서 반복하지 않는다.
- `30년`, `30년+`는 `/about/history`의 확인된 연혁에서만 사용한다.
- 장애와 어려움을 후원 참여를 유도하는 장치로 사용하지 않는다.
- 행정용어와 복지 전문용어는 쉬운 한국어로 풀어 쓴다.

## 6. 사진과 이미지

- 승인된 실제 시설·공간·활동 사진을 최우선으로 사용한다.
- 스톡 사진과 AI 생성 인물을 실제 거주인이나 시설 모습처럼 사용하지 않는다.
- 승인 사진이 없으면 사진 영역을 억지로 만들지 않고 콘텐츠 양에 맞게 화면을 축소한다.
- 거주인의 얼굴, 이름, 위치, 일정, 장애·건강 정보를 조합해 개인을 식별할 수 있는지 검수한다.
- 사진은 불쌍함이나 고립보다 생활, 관계, 공간, 활동의 맥락을 보여 줘야 한다.
- 정보 전달에 필요한 사진은 목적을 설명하는 대체 텍스트를 제공한다.
- 장식 이미지는 빈 대체 텍스트를 사용하거나 보조기술에서 제외한다.
- 이미지 안의 글자를 주요 정보 전달 수단으로 사용하지 않는다.

## 7. 색상과 타이포그래피

### 색상

- 현재 녹색·점토색·중립색 토큰은 공식 CI가 정해질 때까지 임시 디자인 자원으로 유지한다.
- 강한 색상 면은 한 화면에서 핵심 영역 하나에만 사용한다.
- 섹션을 구분하기 위해 모든 배경색을 번갈아 사용하지 않는다.
- 상태는 색상만으로 구분하지 않고 텍스트와 형태를 함께 사용한다.

### 타이포그래피

- 큰 제목은 페이지 시작 또는 핵심 콘텐츠에만 사용한다.
- 모든 섹션에 같은 크기의 감성 제목을 반복하지 않는다.
- 본문은 `max-w-content` 읽기 폭과 충분한 행간을 유지한다.
- 작은 글자에 핵심 정보, 날짜, 모집 상태를 숨기지 않는다.
- 외부 웹폰트와 장식 폰트는 공식 브랜드 기준 없이 추가하지 않는다.

## 8. 레이아웃과 카드

- 페이지 목적에 따라 사진 중심, 목록 중심, 문서 중심 레이아웃을 다르게 사용한다.
- 모든 페이지에서 `2열 히어로 → 번호 목록 → 관련 링크` 순서를 반복하지 않는다.
- 카드 한 개가 독립된 정보나 이동 목적을 가질 때만 카드를 사용한다.
- 일반 설명은 제목, 본문, 여백, 구분선으로 표현한다.
- 그림자는 실제로 떠 있는 상호작용 표면 또는 핵심 안내에 제한한다.
- 콘텐츠 양이 적으면 여백과 장식으로 페이지 길이를 억지로 늘리지 않는다.

## 9. 슬라이드와 모션

- 자동 전환이 필요한 슬라이드는 메인 히어로 한 곳으로 제한한다.
- 히어로에는 현재 소개, 최신 활동, 모집 또는 주요 공지처럼 서로 다른 실제 콘텐츠를 사용한다.
- 공개 가능한 슬라이드가 두 개 미만이면 슬라이더를 사용하지 않고 정적 히어로로 표시한다.
- `30년`, 지역명, 추상적인 가치 문장을 슬라이드 수를 채우기 위해 사용하지 않는다.
- 이전·다음·페이지 이동·정지·재생 조작을 제공한다.
- 포인터가 올라가거나 키보드 포커스가 내부에 있으면 자동 전환을 멈춘다.
- `prefers-reduced-motion: reduce`에서는 자동 재생을 시작하지 않는다.
- 생활 이야기의 사진 묶음은 자동재생보다 수동 scroll-snap 또는 목록을 우선한다.
- 배경 영상, 패럴랙스, 의미 없는 등장 애니메이션은 사용하지 않는다.

## 10. 페이지별 시각 역할

### 홈 `/`

- 역할: 주요 콘텐츠로 연결하는 사이트 입구
- 중심: 대표 콘텐츠, 주요 바로가기, 최근 소식
- 금지: 역사 숫자, 위치 통계, 주소 전용 섹션, 소개 페이지 본문 복제
- 슬라이드는 실제 운영 콘텐츠가 있을 때만 사용한다.

### 시설소개 `/about`

- 역할: 시설의 공식 소개와 하위 정보의 시작점
- 중심: 승인된 소개 문구, 대표 사진, 인사말·연혁·찾아오시는 길 이동
- 금지: 주소·전화 상세 반복, `30년+` 통계, 메인 문구 재사용

### 인사말 `/about/greeting`

- 역할: 공식 대표 인사말 제공
- 중심: 승인된 인사말과 공개가 승인된 대표자 정보
- 금지: 임의로 작성한 미션, 대표자 사진과 약력 추정

### 연혁 `/about/history`

- 역할: 확인된 역사 기록 제공
- 중심: 연도와 공식 사건
- 금지: 근거 없는 연도, 성과 카운터, 메인 홍보 문구 재사용

### 찾아오시는 길 `/about/directions`

- 역할: 방문 준비에 필요한 정보 제공
- 중심: 주소, 지도, 교통, 주차, 접근 편의, 연락
- 금지: 다른 페이지에 같은 상세 정보를 반복 배치

### 생활이야기 `/life`

- 역할: 승인된 실제 생활 콘텐츠의 시작점
- 중심: 사진과 짧은 설명, 주요활동과 생활공간 이동
- 금지: 시설의 공식 운영 철학처럼 보이는 임의 문장, 정책 설명 중심 화면

### 소식 `/news`

- 역할: 공지사항과 활동소식 탐색
- 중심: 제목, 분류, 게시일, 중요 상태
- 금지: 게시물이 적을 때 불필요한 검색·필터·큰 히어로 추가

### 함께하기 `/support`

- 역할: 확인된 자원봉사와 후원 절차 안내
- 중심: 대상, 방법, 절차, 문의
- 금지: 죄책감 유발 문구, 확인되지 않은 계좌·모집 일정·신청 폼

### 정보공개 `/transparency`

- 역할: 공개 승인된 자료 탐색
- 중심: 자료명, 기간, 게시일, 파일 정보
- 금지: 일반 홍보 카드와 같은 표현, 자료가 없을 때 가짜 문서 생성

## 11. 헤더와 푸터

### 헤더

- 로고, 상위 메뉴, 함께하기 강조 행동으로 구성한다.
- `서울 강서구`를 전역 홍보 문구로 표시하지 않는다.
- 실제 하위 페이지가 있는 메뉴에만 접근 가능한 드롭다운을 제공한다.
- 모바일은 같은 계층의 아코디언 메뉴를 사용한다.

### 푸터

- 주소와 대표 전화는 푸터에서 한 번만 간단히 제공한다.
- 찾아오시는 길, 개인정보처리방침, 인스타그램 등 실제 경로만 제공한다.
- 상위 메뉴 전체를 다시 큰 목록으로 반복하지 않는다.

## 12. 접근성 기준

- WCAG 2.2 AA를 목표로 하되 전문 검증 전 적합 또는 인증 완료로 표현하지 않는다.
- 의미 있는 제목 순서와 랜드마크를 사용한다.
- 모든 기능을 키보드로 사용할 수 있어야 한다.
- 포커스가 sticky 헤더와 팝업에 가려지지 않아야 한다.
- 최소 조작 영역은 44px 이상으로 유지한다.
- 320px reflow, 200%·400% 확대에서 가로 스크롤과 정보 손실이 없어야 한다.
- 오류, 모집 상태, 현재 위치를 색상만으로 전달하지 않는다.
- 접근성 도구 버튼을 추가하는 것으로 기본 구조 문제를 대신하지 않는다.

## 13. 레퍼런스 적용

- [사랑의열매](https://www.chest.or.kr/): 참여와 정보공개 영역의 계층만 참고한다.
- [푸르메재단](https://purme.org/): 기관소개, 사업, 소식과 독립된 오시는 길 구조를 참고한다.
- [L'Arche International](https://www.larche.org/): 공동체 생활, 소식, 기관 정체성과 연혁의 분리를 참고한다.
- [밀알복지재단](https://www.miral.org/): 공지·사업·자료 목록 구조를 참고한다.
- [NULI](https://nuli.navercorp.com/): 키보드, 명도 대비, 대체 텍스트와 접근성 검증 기준을 참고한다.

후원 캠페인의 감정적 표현, 대규모 기관의 복잡한 메뉴, 고유한 색상·문구·사진·코드는 복제하지 않는다.

## 14. 구현 순서

1. 정보구조와 시각 방향 확정
2. 현재 화면에서 제거할 반복 문구와 위치 정보 목록 확정
3. 헤더·모바일 메뉴·푸터 재구성
4. 메인 랜딩 재설계
5. 시설소개와 찾아오시는 길 구현
6. 생활이야기 재설계
7. 소식, 함께하기, 정보공개 개선
8. 승인된 사진과 공식 문구 연결
9. 반응형·키보드·확대·스크린리더 검증

한 PR에서 전체 페이지를 동시에 수정하지 않는다. 문서 → 내비게이션 → 메인 → 하위 페이지 순서를 지킨다.

## 15. 완료 판단

- 각 페이지가 서로 다른 사용자 목적과 레이아웃을 가진다.
- 메인, 소개, 생활 페이지에 같은 소개 문장이 반복되지 않는다.
- `30년+`와 지역명이 홍보용 통계로 노출되지 않는다.
- 주소 상세는 푸터와 찾아오시는 길에만 존재한다.
- 실제 콘텐츠가 부족할 때 슬라이드, 카드, 페이지 길이를 억지로 채우지 않는다.
- 승인된 사진이 없어도 가짜 이미지 없이 정보 탐색이 가능하다.
- 키보드, 확대, reflow, 동작 감소 환경에서 정보와 기능이 유지된다.
