# 샬롬의 집 공식 홈페이지 정보구조

## 1. 문서 목적

이 문서는 공개 홈페이지의 메뉴, 하위 페이지, 정보 배치 기준을 정의한다. 현재 구현된 화면을 유지하기 위한 문서가 아니라, 방문자가 필요한 정보를 예측 가능한 위치에서 찾도록 사이트 구조를 다시 세우는 기준이다.

## 2. 사이트 역할

샬롬의 집 홈페이지는 사람을 감성적으로 설명하는 홍보물이나 기부 결제 중심 사이트가 아니다. 다음 정보를 편안하고 정확하게 찾는 공식 창구다.

- 샬롬의 집의 공식 소개
- 생활과 활동에 관한 승인된 이야기
- 공지사항과 최근 소식
- 자원봉사와 후원 참여 방법
- 공개 가능한 운영자료
- 연락처와 찾아오시는 길

## 3. 정보구조 원칙

- 각 페이지는 하나의 분명한 사용자 목적을 가진다.
- 기관의 역사, 위치, 활동 사례를 여러 페이지에서 반복하지 않는다.
- 내부 가치 문장보다 사용자가 찾는 실제 정보를 우선한다.
- 확인된 콘텐츠가 없는 메뉴와 하위 페이지는 공개하지 않는다.
- 메뉴명은 고령자와 디지털 사용이 익숙하지 않은 방문자도 이해할 수 있는 쉬운 한국어를 사용한다.
- 데스크톱과 모바일에서 같은 메뉴 계층을 제공한다.
- 현재 구현과 목표 구조를 구분한다.

## 4. 현재 공개 라우트

```text
/
├─ /about
├─ /life
├─ /news
│  └─ /news/[slug]
├─ /support
└─ /transparency
```

현재 라우트는 기존 링크를 유지하기 위한 상위 랜딩 경로로 사용한다. 메인, 소개, 생활 페이지의 현재 문구와 화면 구성은 새 방향에 맞게 교체할 대상이며 최종 디자인 기준으로 간주하지 않는다.

## 5. 목표 상위 메뉴

| 순서 | 메뉴 | 상위 경로 | 역할 |
| ---: | --- | --- | --- |
| 1 | 샬롬의집 | `/about` | 기관 소개와 방문에 필요한 공식 정보 |
| 2 | 생활이야기 | `/life` | 일상생활, 활동, 생활공간 이야기 |
| 3 | 소식 | `/news` | 공지사항과 활동소식 탐색 |
| 4 | 함께하기 | `/support` | 자원봉사와 후원 참여 안내 |
| 5 | 정보공개 | `/transparency` | 공개 승인된 운영 및 후원 자료 |

홈은 로고 링크가 담당하며 상위 메뉴에 중복하지 않는다.

## 6. 목표 하위 정보구조

아래 구조는 구현 목표다. 각 하위 페이지는 필요한 공식 콘텐츠가 확보된 뒤 공개한다.

```text
/about  샬롬의집
├─ 시설소개
├─ /about/greeting       인사말
├─ /about/history        연혁
└─ /about/directions     찾아오시는 길

/life  생활이야기
├─ 일상생활
├─ /life/activities      주요활동
└─ /life/spaces          생활공간

/news  소식
├─ 공지사항
├─ 활동소식
└─ /news/[slug]          게시물 상세

/support  함께하기
├─ /support/volunteer    자원봉사
└─ /support/donation     후원안내

/transparency  정보공개
├─ 운영자료
└─ 후원 관련 공개자료
```

조직도, 직원 소개, 시설 이용 또는 입소 안내는 공개 범위와 실제 콘텐츠가 확인되기 전까지 메뉴에 추가하지 않는다.

## 7. 위치와 연락 정보

주소와 대표 전화는 다음 두 위치에서만 제공한다.

1. 전역 푸터의 간단한 기본 정보
2. `/about/directions`의 상세 방문 안내

다음 배치는 사용하지 않는다.

- 메인 히어로와 통계 영역의 지역명
- 메인 하단의 별도 위치 홍보 섹션
- 소개 페이지 히어로의 지역명과 주소
- 여러 페이지에 반복되는 주소·전화 정보 블록

`/about/directions`에는 확인된 정보만 제공한다.

- 주소
- 지도 또는 외부 지도 링크
- 대중교통
- 주차
- 출입구와 이동 접근 편의
- 방문 전 연락 필요 여부
- 대표 전화

대중교통, 주차, 출입과 방문 시간은 운영자 확인 전 작성하지 않는다.

## 8. 역사 정보 사용 원칙

- `30년`, `30년+`를 브랜드 슬로건, 메인 통계, 히어로 문구로 사용하지 않는다.
- 메인과 시설소개 페이지에서 역사 기간을 반복하지 않는다.
- 정확한 개원 연도와 공식 사건이 확인된 뒤 `/about/history`에서만 연혁으로 제공한다.
- 숫자 카운터나 성과 통계처럼 강조하지 않고 연도와 사건을 읽는 문서 구조로 제공한다.

## 9. 내비게이션 동작

### 데스크톱

- 하위 페이지가 실제로 공개된 상위 메뉴에만 드롭다운을 제공한다.
- 메뉴 버튼과 하위 링크를 키보드로 이동할 수 있어야 한다.
- 포인터 hover만으로 조작을 제한하지 않는다.
- 현재 상위 메뉴와 현재 하위 페이지를 함께 표시한다.

### 모바일

- 상위 메뉴를 아코디언 방식으로 제공한다.
- 상위 랜딩 페이지와 하위 페이지를 모두 선택할 수 있어야 한다.
- 데스크톱과 메뉴명·순서·계층을 동일하게 유지한다.
- 메뉴를 닫아도 포커스가 사라지지 않아야 한다.

### 페이지 내부

- 하위 페이지에는 상위 메뉴로 돌아갈 수 있는 breadcrumb를 제공한다.
- 소개 페이지 안에 주소, 연혁, 인사말을 한 화면에 모두 쌓지 않는다.
- 동일한 관련 링크 목록을 모든 페이지 하단에 반복하지 않는다.

## 10. 콘텐츠 유형

| 유형 | 중심 정보 | 표현 방식 |
| --- | --- | --- |
| 시설소개 | 공식 소개 문장과 기본 역할 | 짧은 본문과 실제 사진 |
| 생활이야기 | 승인된 일상과 활동 | 사진·제목·짧은 설명 |
| 공지사항 | 제목, 게시일, 중요 여부 | 문서형 목록 |
| 활동소식 | 제목, 게시일, 요약, 승인 사진 | 이야기 목록 |
| 참여안내 | 대상, 방법, 절차, 문의 | 단계형 안내 |
| 정보공개 | 문서명, 기간, 게시일, 파일 정보 | 자료 목록 |
| 찾아오시는 길 | 주소, 이동, 접근 편의, 연락 | 지도와 정보 목록 |

## 11. 구현 순서

1. 방향 문서 확정
2. 상위 메뉴와 하위 라우트 설계
3. 헤더·모바일 메뉴·푸터 재구성
4. 메인 랜딩 재설계
5. 시설소개 재설계
6. 찾아오시는 길 독립 페이지 구현
7. 생활이야기 재설계
8. 소식, 함께하기, 정보공개 순서로 구현
9. 승인 사진과 공식 문구 연결
10. 반응형·키보드·확대·스크린리더 검증

## 12. 확인 필요

- 공식 로고와 사용 가능한 원본 파일
- 공식 인사말과 시설소개 문구
- 정확한 개원 연도와 공개 가능한 연혁
- 승인된 시설·생활·활동 사진
- 대중교통, 주차, 출입구 접근 편의와 방문 안내
- 현재 운영 중인 활동과 모집 상태
- 후원과 자원봉사 절차
- 공개 가능한 운영 및 후원 자료

확인되지 않은 항목은 임시 문구, 가짜 날짜, 추정 정보로 채우지 않는다.
