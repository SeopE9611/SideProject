# 정보구조

Design Direction V3는 기존 GNB와 route를 교체하지 않고 그 위에 **User Intent Layer**를 둔다. 사용자는 공식적인 시설 정보와 샬롬의 집의 일상·관계를 서로 구분해 탐색하고, 필요한 때 참여·방문 행동으로 이동한다.

## 주요 방문자 과업

- 샬롬의 집이 어떤 시설인지 확인한다.
- 위치, 연락처와 방문 전 필요한 사항을 확인한다.
- 최근 공지와 활동을 확인한다.
- 자원봉사와 후원 참여 방법을 확인한다.
- 운영 및 후원 공개자료를 확인한다.

## User Intent Layer

| 사용자 목적 | 우선 연결하는 현재 메뉴·route | 탐색 원칙 |
| --- | --- | --- |
| 1. 시설 이해 | `시설소개`(`/about`), `인사말`(`/about/greeting`), `함께하는 사람들`(`/about/people`), `생활공간`(`/about/spaces`) | 공식 설명과 승인된 시설·사람 정보를 먼저 제공한다. |
| 2. 생활/프로그램 확인 | `생활·프로그램`(`/life`), `프로그램`(`/life/programs`), `활동사진`(`/life/gallery`) | 생활 기록, 프로그램 인덱스와 승인 사진을 콘텐츠 성격에 맞게 구분한다. |
| 3. 최신 소식 확인 | `소식`(`/news`), `공지사항`(`/news/notices`), `활동소식`(`/news/activities`) | 공지는 기관 정보, 활동소식은 생활 story로 구분한다. |
| 4. 참여 | `함께하기`(`/support`), `후원하기`(`/support/donation`), `자원봉사`(`/support/volunteer`) | 실제 절차와 문의를 중심으로 안내한다. |
| 5. 방문/문의 | `찾아오시는 길`(`/about/directions`), `문의하기`(`/support/contact`) | 주소·전화·연락 경로를 즉시 사용할 수 있게 한다. |
| 6. 운영 및 공개자료 확인 | `자료공개`(`/transparency`) | 공개 승인된 문서를 분류와 기간으로 찾게 한다. |

이 계층은 새 URL이나 별도 사용자별 사이트를 만들지 않는다. 보호자·가족·방문자, 후원자·자원봉사자, 기관·복지 관계자, 일반 방문자가 같은 IA 안에서 주요 과업을 빠르게 발견하도록 Home과 Navigation의 우선순위를 정하는 관점이다.

## 목표 상위 메뉴

상단 메뉴는 `시설소개`, `생활·프로그램`, `소식`, `함께하기` 순서로 제공한다.
`자료공개`는 `소식`의 하위 메뉴로 제공하되 기존 `/transparency` route를
유지한다. 구현되지 않은 미래 route는 메뉴에 노출하지 않는다.

```text
/
├─ /about
│  ├─ /about/greeting
│  ├─ /about/people
│  ├─ /about/spaces
│  └─ /about/directions
├─ /life
│  ├─ /life/programs
│  └─ /life/gallery
├─ /news
│  ├─ /news/notices
│  ├─ /news/activities
│  ├─ /news/[slug]
│  └─ /transparency
└─ /support
   ├─ /support/donation
   ├─ /support/volunteer
   └─ /support/contact
```

`/transparency`는 URL상 `/news` 하위가 아니지만 메뉴와 탐색 구조에서는 `소식`의 하위인 `자료공개`로 제공한다.

## 메인 페이지 필수 정보와 접근 경로

Home은 전체 sitemap의 축소판이 아니다. 주요 목적과 최신 콘텐츠만 선별하여 기관 식별, 과업 탐색, 기관 소개, 생활 story, 프로그램 인덱스, 공지·활동소식, 참여, 공개자료, 방문·연락으로 연결한다. 상세 순서와 화면 composition은 `page-patterns.md`가 소유한다.

공식 정보인 기관정보·공지·자료공개와 생활 콘텐츠인 활동소식·생활사진·프로그램은 정보 성격을 구분한다. 같은 CMS나 상세 route를 공유하더라도 Home과 목록에서 동일한 시각 문법을 강제하지 않는다. 참여 정보는 별도 과업으로 제공하고 모든 생활 콘텐츠 끝에 후원 CTA를 반복하지 않는다.

데이터가 적으면 항목 수에 맞게 높이를 줄이고, 사진이 없으면 사진 영역을 생략한다. 필수 경로는 메뉴·본문 링크로 유지한다. 콘텐츠 양별 구성은 `page-patterns.md`, 테스트 데이터의 공개 범위는 `content-governance.md`를 따른다.

## 반복 정보

주소와 대표번호를 정확히 두 곳에만 표시한다는 제한은 사용하지 않는다. 상단 유틸리티 영역, 푸터, 찾아오시는 길, 메인 하단 연락·방문 모듈, 문의가 필요한 참여 페이지에는 과업상 필요한 범위에서 반복할 수 있다. 중복 최소화보다 정확성, 최신성, 과업 수행 가능성을 우선한다.

## 페이지 유형

| 페이지        | 레이아웃 유형     |
| ------------- | ----------------- |
| 홈            | 기관 포털형       |
| 시설소개      | 기관 개요형       |
| 생활이야기    | 사진·기록형       |
| 소식          | 검색·분류·목록형  |
| 함께하기      | 절차 안내형       |
| 자료공개      | 문서 라이브러리형 |
| 찾아오시는 길 | 지도·방문 정보형  |

같은 히어로와 같은 레이아웃을 모든 페이지에 적용하지 않는다. 각 유형의 구체적인 구조는 `page-patterns.md`가 소유한다.

## IA 운영 원칙

- 메뉴는 기관 내부 조직보다 사용자 목적을 우선한다. 다만 현재 4개 GNB가 실제 목적과 route를 적절히 연결하므로 V3만을 이유로 변경하지 않는다.
- Home의 선별 노출과 GNB의 전체 탐색 역할을 구분한다. Home에서 빠진 경로도 GNB·지역 내비게이션·Footer에서 찾을 수 있게 한다.
- 공식정보와 생활콘텐츠의 label, metadata와 목록 관계를 혼합하지 않는다.
- 후원·자원봉사는 중요한 행동이지만 기관 이해와 생활 기록을 침범하거나 Home의 최우선 KPI가 되지 않는다.
- 데이터가 없거나 공개 승인이 완료되지 않은 경로를 가짜 콘텐츠로 채우지 않는다.
