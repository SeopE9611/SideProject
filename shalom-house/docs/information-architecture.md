# 샬롬의 집 공식 홈페이지 정보구조

## 1. 문서 목적

이 문서는 공개 홈페이지에서 방문자가 찾을 정보와 이동 경로를 정의한다. 현재 라우트와 향후 검토 대상을 구분하여 메뉴, 콘텐츠, URL 설계의 기준으로 사용한다.

## 2. 정보구조 원칙

- 시설 소개, 생활, 소식, 참여, 운영 투명성 정보를 방문자 관점에서 구분한다.
- 고령자와 디지털 사용이 익숙하지 않은 이용자도 예측할 수 있는 쉬운 한국어 메뉴를 사용한다.
- 공개가 승인된 정보만 배치하며 내부 업무 구조를 공개 메뉴에 그대로 반영하지 않는다.
- 구현 편의보다 정보 탐색과 접근성을 우선한다.
- 현재 구현과 향후 계획을 명확히 구분한다.

## 3. 현재 공개 라우트

```text
/
├─ /about
├─ /life
├─ /news
├─ /support
└─ /transparency
```

현재 여섯 개 공개 라우트는 `src/app/(public)` Route Group 아래에 구성돼 있다. `(public)`은 공개 레이아웃을 공유하기 위한 코드 구조상의 구분이며 URL에는 나타나지 않는다. 각 경로에는 기본 페이지가 있지만 실제 콘텐츠 기능이 완료된 것은 아니다.

## 4. 확정 상위 메뉴와 콘텐츠 범위

| 메뉴 | 경로 | 사용자에게 제공할 정보 | 현재 방향 |
| --- | --- | --- | --- |
| 홈 | `/` | 공동체 정체성과 주요 콘텐츠 진입점 | 로고 링크로 제공하고 상위 메뉴에는 중복하지 않음 |
| 샬롬 소개 | `/about` | 시설 소개와 공식 기본 정보 | 소개·연혁·조직·오시는 길 검토 |
| 생활과 활동 | `/life` | 함께 만드는 일상과 활동 | 프로그램·일상·시설 환경 콘텐츠 검토 |
| 소식과 이야기 | `/news` | 공지사항과 활동 이야기 | 공개 뉴스 목록·상세와 CMS 연결 |
| 함께하기 | `/support` | 후원과 자원봉사 문의 | 개인정보 입력 없이 현재 가능한 문의 절차 안내 |
| 운영 공개 | `/transparency` | 운영 및 후원 관련 공개 자료 | 공개 가능한 보고자료 관리 검토 |

상위 메뉴명과 순서는 확정하되, 하위 정보는 실제 콘텐츠 양과 공개 승인 범위가 확인된 뒤 독립 라우트 여부를 결정한다.

## 5. 향후 하위 정보구조

다음 항목은 확정 라우트가 아닌 검토 대상이다.

```text
/about
├─ 시설 소개
├─ 미션과 운영 방향
├─ 연혁
├─ 조직 및 직원 공개 범위
├─ 시설 환경
└─ 오시는 길

/life
├─ 생활 안내
├─ 주요 프로그램
├─ 활동 이야기
└─ 시설 이용 관련 안내

/news
├─ 공지사항
├─ 활동 소식
└─ 게시물 상세

/support
├─ 후원 안내
├─ 자원봉사 안내
├─ 참여 절차
└─ 문의 방법

/transparency
├─ 운영 보고
├─ 후원금 관련 공개자료
├─ 예산·결산 공개자료
└─ 기타 공시자료
```

각 항목은 운영자 협의 후 독립 라우트 또는 콘텐츠 분류로 확정한다. 공개할 실제 내용과 명칭도 함께 확인해야 한다.

## 6. 공개 영역과 관리자 영역의 관계

- 공개 영역은 방문자가 승인된 홈페이지 콘텐츠를 열람하는 사이트다.
- 관리자 영역은 향후 공개 콘텐츠를 관리하기 위한 비공개 영역이다.
- 현재 관리자 라우트는 없다.
- 관리자 영역은 공개 Route Group과 분리해서 설계할 예정이다.
- 일반 사용자의 회원가입, 로그인, 마이페이지는 초기 정보구조에 포함하지 않는다.
- 관리자 URL과 인증 방식은 추후 인증 설계에서 결정한다.

## 7. 콘텐츠 유형

향후 다음 콘텐츠 유형을 다룰 수 있다.

- 고정 페이지 콘텐츠
- 공지사항
- 활동 소식
- 후원 안내
- 자원봉사 안내
- 투명성 자료
- 이미지
- 공개용 첨부파일
- 연락 및 위치 정보

이 구분은 정보구조를 위한 후보이며 아직 DB 모델이나 CMS 스키마로 확정되지 않았다.

## 8. 내비게이션 원칙

- 메뉴명은 쉽고 일관된 한국어를 사용한다.
- 한 메뉴에 지나치게 많은 하위 항목을 배치하지 않는다.
- 후원·자원봉사·연락 경로를 쉽게 찾을 수 있도록 구성한다.
- 현재 위치를 이해할 수 있도록 페이지 제목과 경로를 제공한다.
- 키보드만으로 전체 메뉴에 접근할 수 있어야 한다.
- 모바일 내비게이션과 데스크톱 내비게이션의 정보구조를 일치시킨다.
- 모바일에서는 메뉴명 아래 한 줄 설명을 함께 제공한다.
- 현재 하위 라우트가 하나뿐인 상위 메뉴에는 드롭다운을 만들지 않는다.
- 관리 편의를 이유로 사용자 메뉴 구조를 복잡하게 만들지 않는다.

## 9. URL 및 라우트 원칙

- 현재 공개 경로는 변경 필요성과 영향을 검토한 뒤 조정한다.
- URL은 짧고 일관되며 콘텐츠의 목적을 예측할 수 있도록 구성한다.
- Route Group 이름은 URL에 포함하지 않는다.
- 목록·상세 URL, 분류, 식별자 형식은 콘텐츠 모델 확정 후 결정한다.
- 경로를 변경할 때는 기존 링크와 검색 결과에 대한 이동 안내 또는 연결 유지 방안을 검토한다.
- 관리자 경로를 공개 메뉴에 노출하지 않으며 인증만으로 보호가 완성된다고 가정하지 않는다.

## 10. 미확정 항목

다음 항목은 **확인 필요** 상태이며 운영자 협의 또는 추후 구현 단계에서 결정한다.

- 하위 항목을 독립 라우트로 만들지, 상위 페이지의 콘텐츠 분류로 둘지 여부
- 시설 이용 및 입소 안내의 공개 여부와 범위
- 연락 및 방문 안내의 위치와 공개 정보
- 공지사항, 활동 소식, 투명성 자료의 상세 URL 규칙
- 검색, 분류, 페이지 나누기 제공 여부
- 관리자 URL과 인증 방식
- CMS 및 DB 콘텐츠 모델
