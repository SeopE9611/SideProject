# 샬롬의 집 메인 랜딩 재설계 기준

## 1. 문서 목적

이 문서는 메인페이지를 처음부터 다시 설계하기 위한 실행 기준이다. 현재 메인의 섹션 순서, 슬라이드 문구, 통계와 위치 영역을 개선하는 것이 아니라 새 정보구조에 맞게 교체한다.

## 2. 메인의 역할

메인페이지는 시설의 모든 정보를 설명하는 소개 페이지가 아니다. 방문자가 현재 확인할 수 있는 핵심 콘텐츠와 필요한 경로를 빠르게 찾는 사이트 입구다.

우선순위는 다음과 같다.

1. 현재 가장 중요한 대표 콘텐츠
2. 자주 찾는 주요 경로
3. 최근 공지사항과 활동소식
4. 승인된 생활 이야기
5. 실제 참여 방법과 정보공개

## 3. 사용하지 않을 메시지

- `30년`, `30년+` 역사 강조
- `서울 강서구` 위치 강조
- 주소와 대표 전화를 통계처럼 표현하는 영역
- `시설보다 먼저`, `함께 사는 집`, `존중과 일상`의 반복
- 공개 콘텐츠 수를 채우기 위한 추상적인 가치 슬라이드
- 소개 페이지와 생활 페이지 본문을 줄여서 반복한 섹션

역사는 `/about/history`, 위치 상세는 `/about/directions`, 시설 소개는 `/about`에서 담당한다.

## 4. 화면 규격

| 항목 | 모바일 | 넓은 화면 | 코드 기준 |
| --- | ---: | ---: | --- |
| 사이트 최대 폭 | 화면 폭 | 1,280px | `max-w-site` |
| 읽기 본문 최대 폭 | 화면 폭 | 736px | `max-w-content` |
| 페이지 좌우 여백 | 20px | 48px | `px-page`, `px-page-wide` |
| 기본 섹션 상하 여백 | 80px | 112px | `py-section`, `py-section-wide` |
| 히어로 제목 상한 | 42px | 72px | `text-hero`, `text-hero-lg` |
| 일반 페이지 큰 제목 | 40px | 56px | `text-display`, `text-display-lg` |
| 본문 | 17px / 1.75 | 동일 | `text-body` |
| 최소 조작 영역 | 44px | 44px 이상 | `min-h-11`, `min-w-11` |

규격은 최대값이며 모든 제목과 섹션을 이 크기로 만들라는 의미가 아니다. 콘텐츠 양과 위계에 따라 더 작은 크기와 여백을 사용한다.

## 5. 메인 구성

### 1. 대표 히어로

히어로는 현재 가장 중요한 콘텐츠를 보여 준다.

사용 가능한 콘텐츠 유형:

- 승인된 대표 사진과 공식 소개
- 최근 활동소식
- 현재 모집 중인 자원봉사
- 중요 공지사항

두 개 이상의 실제 콘텐츠가 있을 때만 슬라이더를 사용한다. 콘텐츠가 한 개면 정적 히어로로 표시한다.

### 2. 주요 바로가기

메인에서 우선 연결할 경로는 네 개로 제한한다.

- 시설소개
- 생활이야기
- 자원봉사
- 찾아오시는 길

모든 상위 메뉴를 동일한 카드로 반복하지 않는다. 바로가기는 짧은 이름과 분명한 이동 결과를 제공한다.

### 3. 최근 소식

- 공개된 실제 게시물만 표시한다.
- 공지사항과 활동소식을 분류 레이블로 구분한다.
- 제목, 게시일, 짧은 요약을 중심으로 구성한다.
- 게시물이 없으면 짧은 정상 빈 상태만 표시한다.
- 데모 게시물과 가짜 날짜를 사용하지 않는다.

### 4. 생활 이야기

- 승인된 실제 사진과 짧은 설명이 있을 때만 제공한다.
- 활동 세 개를 채우기 위해 과거 사례를 고정 반복하지 않는다.
- 사진이 없으면 추상 그래픽으로 대체하지 않고 영역을 축소하거나 생략한다.
- 상세 내용은 `/life` 또는 실제 활동소식으로 연결한다.

### 5. 함께하기와 정보공개

- 현재 운영이 확인된 자원봉사 또는 후원 방법만 강조한다.
- 참여 방법이 미확정이면 강한 행동 버튼을 제공하지 않는다.
- 공개된 운영자료가 있을 때 최근 자료 또는 정보공개 경로를 연결한다.
- 참여와 정보공개를 같은 감성 홍보 카드로 묶지 않는다.

### 6. 푸터

- 주소와 대표 전화는 푸터에서 한 번만 제공한다.
- 찾아오시는 길, 개인정보처리방침, 인스타그램 등 실제 링크를 제공한다.
- 메인 본문에 별도의 위치·연락 섹션을 만들지 않는다.

## 6. 히어로 슬라이더 규칙

- 실제 콘텐츠가 두 개 이상일 때만 활성화한다.
- 최대 슬라이드 수는 3개다.
- 첫 화면의 핵심 정보와 CTA는 슬라이드가 멈춰도 이해할 수 있어야 한다.
- 이전, 다음, 특정 슬라이드 이동, 정지·재생 버튼을 제공한다.
- 자동 전환 간격은 최소 8초로 한다.
- 포인터가 올라가거나 키보드 포커스가 내부에 있으면 자동 전환을 멈춘다.
- `prefers-reduced-motion: reduce`에서는 자동 재생을 시작하지 않는다.
- 자동 변경을 스크린리더 라이브 영역으로 반복 공지하지 않는다.
- `30년`, 위치, 추상적인 가치 문장을 슬라이드 수를 채우기 위해 사용하지 않는다.
- 메인 외 영역에 두 번째 자동 슬라이더를 추가하지 않는다.

## 7. 콘텐츠 준비 조건

| 영역 | 최소 필요 콘텐츠 | 부족할 때 처리 |
| --- | --- | --- |
| 대표 히어로 | 승인 사진 또는 공식 소개 1개 | 정적 텍스트 히어로 |
| 히어로 슬라이더 | 서로 다른 실제 콘텐츠 2개 이상 | 슬라이더 비활성화 |
| 최근 소식 | 공개 게시물 1개 이상 | 간결한 빈 상태 |
| 생활 이야기 | 승인 사진과 설명 1개 이상 | 영역 축소 또는 생략 |
| 함께하기 | 현재 참여 방법과 문의 경로 | 안내 페이지 링크만 제공 |
| 정보공개 | 공개 승인 자료 1개 이상 | 정보공개 페이지 링크만 제공 |

콘텐츠가 없다는 이유로 임시 슬로건, 가짜 통계, 장식 카드, 추상 이미지를 추가하지 않는다.

## 8. 접근성

- 키보드만으로 메뉴, 슬라이더, 모든 링크를 사용할 수 있어야 한다.
- 슬라이더 정지 버튼은 찾기 쉽고 접근 가능한 이름을 가져야 한다.
- 포커스가 sticky 헤더에 가려지지 않아야 한다.
- 320px reflow에서 가로 스크롤과 잘린 조작 요소가 없어야 한다.
- 200%·400% 확대에서 정보와 기능이 유지돼야 한다.
- 텍스트가 사진 위에 놓이면 실제 이미지별 명도 대비를 검증한다.
- 사진 없이도 제목, 요약, 링크만으로 내용을 이해할 수 있어야 한다.
- 상태와 현재 위치를 색상만으로 전달하지 않는다.

## 9. 구현 범위와 순서

### 선행 작업

1. `siteConfig.mainNavigation`을 새 상위 메뉴 구조로 변경
2. 하위 메뉴 데이터 구조 정의
3. 데스크톱 드롭다운과 모바일 아코디언 구현
4. 푸터 정보와 링크 재구성

### 메인 작업

1. 현재 고정 슬라이드 문구 제거
2. `30년+`, 지역명, 위치·연락 섹션 제거
3. 실제 콘텐츠 조건에 따른 정적 히어로와 슬라이더 상태 구현
4. 주요 바로가기 구현
5. 최근 소식 목록 연결
6. 승인 콘텐츠 유무에 따른 생활 이야기 영역 구현
7. 함께하기와 정보공개 경로 정리

### 검증

1. 정적 검색으로 금지 문구와 주소 중복 확인
2. 타입 검사
3. 데스크톱·모바일 메뉴 키보드 검증
4. 슬라이더 정지·재생·동작 감소 검증
5. 320px, 200%, 400% reflow 확인
6. CI lint·typecheck·build 확인

## 10. 구현 PR 분리

1. 헤더·하위 메뉴·푸터
2. 메인 콘텐츠 구조와 반복 문구 제거
3. 히어로 정적·슬라이더 상태
4. 실제 사진과 공식 콘텐츠 연결
5. 메인 반응형·접근성 최종 QA

한 PR에서 내비게이션, 메인, 모든 하위 페이지를 동시에 수정하지 않는다.

## 11. 완료 판단

- 메인에서 `30년+`, 지역명 통계, 주소 전용 섹션이 제거됐다.
- 메인은 소개 페이지의 본문을 반복하지 않는다.
- 실제 콘텐츠 수에 따라 정적 히어로와 슬라이더가 결정된다.
- 주요 바로가기로 시설소개, 생활이야기, 자원봉사, 찾아오시는 길을 찾을 수 있다.
- 최근 소식은 실제 공개 게시물만 표시한다.
- 주소와 대표 전화는 푸터에서 한 번만 제공된다.
- 콘텐츠가 부족해도 가짜 문구와 장식 요소로 화면을 채우지 않는다.
- 키보드, 확대, reflow, 동작 감소 환경에서 정보와 기능이 유지된다.
