# 웹 접근성 기준

## 문서 목적과 적용 기준

이 문서는 장애인과 고령자를 포함한 모든 사용자가 공개 정보와 기능을 이용하기 위한 장기 기준이다. WCAG 2.2 AA를 우선 설계 목표로 하고 국내 웹 콘텐츠 접근성 지침 2.2를 함께 검토한다. 법률 자문이나 품질인증을 대신하지 않으며 자동·정적 검사만으로 적합을 선언하지 않는다. 과거 결과는 `audits/`의 날짜별 기록으로 분리하고 실행하지 않은 검사는 통과로 표현하지 않는다.

## 구조와 탐색

- 문서 언어를 `ko`로 지정하고 `header`, `nav`, 단일 `main`, `footer`를 의미에 맞게 사용한다.
- 본문 바로가기, 논리적인 제목 단계와 현재 위치를 제공한다.
- 이동은 링크, 동작은 버튼을 사용하며 이름만으로 목적을 이해할 수 있게 한다.
- 기본 HTML을 우선하고 ARIA는 필요한 역할·상태·이름을 보완할 때만 사용한다.

## 정량 검증값

### 색상 대비

- 일반 텍스트는 최소 `4.5:1`, 큰 텍스트는 최소 `3:1`이다.
- 기능적 UI 경계와 상태 표시는 최소 `3:1`이다.
- 실제 배경과 투명도를 포함해 hover, focus, active, disabled 상태별로 검사한다.
- 상태, 오류, 선택과 중요도를 색상만으로 전달하지 않는다.

### 텍스트 간격

다음 사용자 스타일을 적용해도 콘텐츠나 기능의 손실, 잘림과 겹침이 없어야 한다.

```text
line-height: 1.5
paragraph spacing: 2em
letter spacing: 0.12em
word spacing: 0.16em
```

### 확대와 reflow

- 브라우저 `200%` 및 `400%` 확대와 `320 CSS px` 폭에서 정보·기능 손실과 불필요한 가로 스크롤이 없어야 한다.
- 본질적으로 2차원인 표, 지도, 코드 영역은 예외로 별도 스크롤 컨테이너와 식별 가능한 이름을 제공한다.

### 대상 크기

- 주요 상호작용 영역은 가능한 한 `44 × 44 CSS px`를 확보한다.
- 작은 인라인 링크는 주변 간격과 문맥을 함께 검토하고 인접 대상 사이에 오작동 방지 간격을 둔다.

## 키보드, 포커스와 SPA 이동

- 모든 기능을 키보드로 조작하고 논리적 순서와 고정 헤더에 가려지지 않는 `:focus-visible` 표시를 제공한다.
- 메뉴와 오버레이의 열기·닫기, `Escape`, 키보드 함정 여부를 실제 브라우저에서 확인한다.
- Next.js App Router 페이지 이동 후 문서 제목이 변경되어야 한다. 클라이언트 경로 이동 후 포커스와 화면 읽기 흐름은 실제 브라우저와 스크린리더에서 확인한다.
- 모바일 메뉴에서 이동 후 열린 상태와 포커스가 남지 않아야 한다.
- 모달·드로어·드롭다운을 닫으면 적절한 트리거로 포커스를 복귀한다.

현재 코드가 위 이동·포커스 기준을 충족한다고 미리 선언하지 않는다.

## 이미지와 미디어

- 정보 이미지에는 목적과 맥락에 맞는 대체 텍스트를 제공한다. fixture와 placeholder도 그 이유만으로 빈 `alt`를 쓰지 않는다.
- 시각적 의미가 전혀 없는 장식 이미지만 빈 `alt`를 사용한다.
- 대체 텍스트에서 외모나 장애를 불필요하게 묘사하지 않는다.
- 영상에는 자막, 대본과 필요한 화면해설을 검토하고 음성만으로 필수 정보를 전달하지 않는다.
- `prefers-reduced-motion`을 존중하고 자동 재생, 깜빡임과 과도한 패럴랙스를 사용하지 않는다.

## 폼과 인증

현재 공개 폼이 없더라도 향후 구현 기준으로 유지한다.

- `label`과 입력을 연결하고 `autocomplete` 값을 검토한다.
- 오류 요약과 필드별 오류에 위치, 원인과 해결 방법을 제공한다.
- 필수 여부를 색상과 별표에만 의존하지 않고 이전 단계 입력을 불필요하게 반복 요구하지 않는다.
- 인증이 퍼즐, 기억, 전사 같은 인지 테스트에만 의존하지 않게 한다.
- 제출 중, 성공과 실패 상태를 텍스트로 제공하고 비활성 버튼만으로 오류 원인을 숨기지 않는다.

## 패턴별 기준

- **카드**: 제목과 설명의 읽기 순서를 유지하고 카드 전체 링크 안에 다른 상호작용 요소를 중첩하지 않는다.
- **목록**: `ul`·`ol`을 사용하고 제목, 분류, 날짜와 상태의 관계를 읽기 순서로 이해하게 한다.
- **검색·필터**: 영구 레이블, 적용 조건, 결과 수, 결과 없음과 초기화 방법을 텍스트로 알리고 결과 갱신과 포커스를 검증한다.

## PDF와 첨부파일

- 핵심 정보는 가능한 한 HTML로도 제공하고 스캔 이미지만 존재하는 PDF를 지양한다.
- 링크 전에 문서 제목, 기준 기간, 게시일, 수정일, 형식과 크기를 제공한다.
- PDF 제목, 태그, 읽기 순서, 표 헤더, 링크와 대체 텍스트를 별도로 검증한다.
- 다운로드와 새 창 여부를 사전 안내하고 접근 가능한 대체 형식 문의 경로를 검토한다.

## 수동 검증 매트릭스

| 구분 | 검증 환경 |
| --- | --- |
| 경로 | `/`, `/about`, `/life`, `/news`, `/support`, `/transparency`, 신규 하위 경로, 404 |
| 화면 너비 | 320, 390, 768, 1024, 1440px |
| 확대 | 100%, 200%, 400% |
| 입력 | 키보드, 마우스, 터치 |
| 모션 | 기본, `prefers-reduced-motion` |
| 색상 | 기본, `forced-colors` |
| 보조기술 | 가능한 환경에서 NVDA, VoiceOver, TalkBack |

실제로 실행한 환경만 통과로 기록하며 브라우저·운영체제·보조기술 버전도 남긴다.

## 이슈 기록 형식과 심각도

```text
ID
발견일
상태
심각도
대상 경로
대상 파일 또는 컴포넌트
관련 기준
검사 환경
재현 절차
현재 결과
예상 결과
사용자 영향
수정 방향
검증 결과
```

- **차단**: 핵심 정보·기능에 접근할 수 없거나 키보드 함정, 심각한 개인정보·안전 문제가 있다.
- **높음**: 주요 기능 사용이 크게 어렵거나 포커스 유실, 확대 시 핵심 정보 손실이 있다.
- **보통**: 우회할 수 있으나 반복적인 혼란이나 불편이 발생한다.
- **낮음**: 핵심 사용을 차단하지 않는 일관성·편의 개선 사항이다.

심각도는 수정 난이도가 아니라 사용자 영향으로 판단한다. 자동 검사, 정적 확인, 실제 브라우저, 키보드, 스크린리더와 사용자 검사를 구분하고 미실행 환경은 `미실행` 또는 `확인 필요`로 남긴다.
