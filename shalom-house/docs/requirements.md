# 샬롬의 집 공식 홈페이지 요구사항

## 1. 문서 목적

이 문서는 구현 전에 프로젝트 범위를 통제하기 위한 장기 기준 문서다. 디자인·개발·콘텐츠 작업에서 공통 판단 기준으로 사용한다. 확정되지 않은 사실을 대신하는 시설 소개 문서가 아니며, 확인되지 않은 정보는 `확인 필요`로 관리한다.

## 2. 프로젝트 개요

샬롬의 집 공식 홈페이지는 장애인거주시설의 공공 정보 제공과 소통을 위한 웹사이트다. 쇼핑몰이나 회원제 커뮤니티가 아니다. 시설 소개, 생활과 프로그램, 소식, 참여 방법, 운영 투명성 자료를 방문자가 쉽게 확인하도록 하는 것을 초기 서비스 범위로 삼는다.

## 3. 프로젝트 목표

- 공식적이고 신뢰할 수 있는 시설 정보를 제공한다.
- 시설의 일상과 활동을 거주인을 존중하는 방식으로 전달한다.
- 후원 및 자원봉사 참여 경로를 쉽게 제공한다.
- 운영 투명성 자료에 대한 접근성을 개선한다.
- 관리자가 개발자 도움 없이 주요 공개 콘텐츠를 관리할 수 있는 기반을 마련한다.
- 고령자와 디지털 사용이 익숙하지 않은 이용자도 사용할 수 있는 정보구조를 제공한다.

## 4. 주요 이용자

- 시설과 운영 정보를 확인하려는 일반 방문자
- 거주인의 보호자 및 가족
- 후원 또는 자원봉사를 검토하는 방문자
- 시설 소식과 투명성 자료를 확인하려는 지역사회 관계자
- 홈페이지 공개 콘텐츠를 관리하는 시설 관리자

## 5. 초기 구현 범위

- 시설 소개
- 생활 및 프로그램 안내
- 공지와 활동 소식
- 후원 및 자원봉사 안내
- 운영 투명성 자료
- 연락 및 방문 안내
- 향후 관리자 전용 콘텐츠 관리 기능을 도입할 수 있는 기반

현재 저장소에는 공개 라우트, 공통 공개 레이아웃, 페이지별 플레이스홀더, 404 페이지가 있다. 실제 시설 콘텐츠, DB, 로그인, CMS는 아직 구현되지 않았다.
Vercel 프로젝트와 Preview 배포 연동은 존재하지만, 정식 운영 도메인과 프로덕션 배포 정책은 아직 확정되지 않았다.

## 6. 초기 범위 제외 항목

- 일반 사용자 회원가입 및 일반 사용자 로그인
- 소셜 로그인
- 공개 커뮤니티와 실시간 채팅
- 온라인 결제와 쇼핑몰 기능
- 거주인별 개인 계정과 보호자용 개인 포털
- 내부 전자결재와 직원 인사관리
- 거주인 사례관리
- 의료·건강 기록, 상담 기록, 개별 서비스 지원계획 관리
- 내부 행정 시스템 대체

## 7. 기능 요구사항

### 현재 기반

- `/`, `/about`, `/life`, `/news`, `/support`, `/transparency` 공개 홈페이지 라우트
- 헤더, 본문, 푸터를 포함하는 공통 공개 레이아웃
- 향후 콘텐츠를 안내하는 페이지별 플레이스홀더
- 찾을 수 없는 경로를 안내하는 404 페이지

이 기반은 콘텐츠 및 업무 기능의 구현 완료를 의미하지 않는다.

### 향후 계획

- 시설 소개 콘텐츠
- 생활·프로그램 콘텐츠
- 공지사항과 활동 소식 목록·상세
- 후원 및 자원봉사 안내
- 운영 투명성 자료 목록·상세
- 관리자 전용 로그인
- 관리자 전용 콘텐츠 작성·수정·공개 관리
- 이미지와 첨부파일 관리
- 게시물 임시저장·공개·비공개 상태
- 작성자와 수정일 등 기본 관리 정보
- 중요 변경에 대한 감사 기록 검토

위 항목은 향후 구현 계획이며 현재 구현된 기능이 아니다. 세부 기술과 우선순위는 추후 구현 단계에서 결정한다.

## 8. 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 접근성 | 시맨틱 HTML, 키보드 탐색, 명확한 포커스, 충분한 색상 대비, 이미지 대체 텍스트, 텍스트 확대 대응, 과도한 움직임 최소화, 쉬운 한국어를 고려한다. WCAG 2.2 AA 수준을 설계 목표로 삼되 전문 검증 전에는 공식 적합 인증을 받은 것처럼 표현하지 않는다. |
| 반응형 | 모바일·태블릿·데스크톱에서 같은 정보에 접근할 수 있도록 설계한다. |
| 개인정보 보호 | 공개에 필요한 최소 정보만 처리하고 개인정보 및 민감정보가 콘텐츠나 파일에 포함되지 않도록 검수한다. |
| 보안 | 관리자 인증, 권한, 입력 및 파일 검증, 비밀정보 보호 방안은 구현 단계에서 검토한다. 법적 적합성을 근거 없이 확정하지 않는다. |
| 성능 | 불필요하게 큰 자원과 요청을 줄이고 주요 콘텐츠를 안정적으로 제공한다. 확정되지 않은 성능 수치는 요구사항으로 단정하지 않는다. |
| 검색엔진 기본 대응 | 의미 있는 제목, 설명, 문서 구조와 검색 가능한 공개 콘텐츠를 제공한다. 개인정보가 검색 결과에 노출되지 않도록 한다. |
| 유지보수성 | 공개 영역과 관리자 영역의 책임을 분리하고 일관된 용어와 콘텐츠 구조를 사용한다. |
| 콘텐츠 정확성 | 공식 담당자가 확인한 최신 정보만 공개하고 오래된 정보는 정기적으로 검토한다. |
| 실패 상황 안내 | 찾을 수 없는 페이지, 처리 실패, 권한 부족 등 실패 상황을 이해하기 쉬운 문구와 다음 행동으로 안내한다. |
| 관리자 사용 편의성 | 개발 지식 없이 주요 공개 콘텐츠를 관리할 수 있는 흐름을 목표로 하며 구체적인 화면과 기능은 추후 결정한다. |

## 9. 개인정보 및 민감정보 원칙

홈페이지 DB에는 공개 홈페이지 운영에 필요한 콘텐츠만 저장한다. 다음 정보는 홈페이지 DB에서 제외한다.

- 거주인의 상세 장애 정보, 진단명과 의료기록, 복약 정보
- 상담 기록과 개인별 지원계획
- 보호자 연락처와 가족관계 정보
- 주민등록번호와 내부 생활기록
- 직원 인사자료
- 비공개 후원자 정보
- 내부 행정문서

여러 공개 정보의 조합으로 개인을 알아볼 수 있는지도 검토한다. 공개 여부가 불분명하면 우선 게시하지 않고 운영자 및 필요한 경우 전문가의 확인을 거친다.

## 10. 관리자 운영 방향

- 일반 회원 시스템이 아니라 관리자 전용 인증을 검토한다.
- 관리자는 공개 홈페이지 콘텐츠만 관리하며 내부 복지 행정 시스템을 대체하지 않는다.
- 역할과 권한은 인증 설계 단계에서 확정한다.
- 중요한 게시물은 작성과 공개 승인을 분리하는 방안을 검토한다.
- 관리자 계정과 활동 기록 정책은 추후 별도 문서로 확정한다.
- 관리자 기능과 인증은 현재 구현되지 않았으며 향후 계획이다.

## 11. 벤치마킹 원칙

사랑의열매 사이트는 정보구조와 공익 사이트 사용성을 참고하기 위한 벤치마킹 대상이다. 디자인, 문구, 이미지, 코드, 고유 콘텐츠는 복제하지 않는다. 참고 결과는 샬롬의 집 이용자, 콘텐츠, 접근성 목표에 맞게 독립적으로 검토한다.

## 12. 아직 결정되지 않은 사항

다음 항목은 모두 **확인 필요** 상태다.

- 공식 시설 소개 문구
- 정확한 연혁
- 조직도와 직원 공개 범위
- 현재 코드에 등록된 주소와 대표 전화번호의 공식 최종 확인
- 주소·전화번호 변경 시 검증 및 갱신 책임자
- 추가 연락처, 이메일, 방문 안내의 공개 범위
- 입소 안내 공개 여부
- 후원 계좌와 결제 방식
- 자원봉사 신청 방식
- CMS와 DB
- 관리자 인증 방식
- 파일 저장소
- 정식 운영 도메인
- 프로덕션 배포 및 승인 절차
- 배포 권한과 환경변수 관리 방식
- 운영 담당자와 승인 절차
- 개인정보 보유기간
- 사진·영상 동의 절차의 공식 양식

시설 정보와 운영 절차는 운영자 협의가 필요하다. 기술 선택은 추후 구현 단계에서 결정한다.

## 13. 문서 관리 원칙

- 구현 범위나 확정 방침이 바뀌면 관련 문서를 함께 갱신한다.
- 현재 구현, 향후 계획, 미확정 사항을 구분한다.
- 확인되지 않은 시설 정보나 법적 요건을 추측해 기록하지 않는다.
- 요구사항 변경은 운영자 확인과 공개·개인정보 원칙 검토를 거친다.
- 이 문서는 일회성 작업 보고서가 아니라 프로젝트 전 과정에서 유지하는 기준 문서다.
