# 페이지 패턴 — V4

디자인 언어는 `design-system.md`, 콘텐츠 공개 조건은 `content-governance.md`, 기능과 데이터 계약은 기존 도메인 코드를 따른다. 아래는 화면 유형별 목표이며 빈 상태를 채우려고 콘텐츠를 생성하지 않는다.

## Home

1. 기관명과 시설 설명, 현재 공개 가능한 활동사진을 보여 준다.
2. 사진이 있으면 사용자 조작 이전/다음 버튼과 제목·순서를 제공한다. 0건이면 사진 자리를 렌더링하지 않는다. 조회 오류를 정상 0건으로 안내하지 않는다.
3. 시설소개 / 생활과 프로그램 / 후원·자원봉사 / 방문·연락 바로가기를 짧게 제공한다.
4. 소개 문장과 시설 facts 3개, 활동사진, 프로그램 인덱스, 공지와 활동소식, 참여, 자료공개, 방문·연락을 서로 다른 표현으로 배치한다.
5. CMS 값과 public media proxy를 유지한다. API URL의 공개 조건이나 no-store를 바꾸지 않는다.

## 시설소개

- `/about`: 기본 정보 3개, 운영 원칙과 생활 모습, 관련 안내와 연락 경로. 주요 본문과 보조 탐색의 폭을 구분한다.
- `/about/greeting`: 짧은 제목 블록과 읽기 폭의 문단. 실제 공개 설정에 따른 직책·이름만 표시한다.
- `/about/people`: 역할·담당 업무 중심의 목록. 이름 공개 미승인 시 이름을 렌더링하지 않는다. 장식용 인물 사진을 생성하지 않는다.
- `/about/spaces`: 제목·설명과 선택적 실제 사진. media가 없으면 text-only. 가짜 이미지 영역을 만들지 않는다.
- `/about/directions`: 주소·지도 링크를 짙은 녹색 영역, 전화·방문 문의를 따뜻한 중립 영역에 배치한다. 중복 01/02/03 단계는 추가하지 않는다. 네이버/카카오 외부 링크와 전화·온라인 문의를 유지한다.

## 생활·프로그램

- `/life`: 대표 사진과 보조 기록, 활동소식, 프로그램을 구분한다. 모두 0건이면 하나의 안내로 통합하되 조회 실패는 별도로 표시한다.
- `/life/programs`: 분류·제목·요약·목적·실제 운영 상태의 인덱스. 이미지가 있으면 보조 열, 없으면 본문만 사용한다.
- `/life/gallery`: 데스크톱 두 열에서 사진 크기를 확보하고 좌우 시작점을 달리한다. 모바일 단일 열. 사진과 제목 모두 상세로 연결한다.
- 사진 원본 비율·alt·공개 proxy·날짜 원본은 유지한다. 첫 화면의 요청 우선순위를 제한하고 이후 이미지는 lazy loading한다.

## 소식과 자료공개

- `/news`, `/news/notices`, `/news/activities`: 제목/세부 메뉴, 검색 도구, 결과 수, 구분선 목록, 페이지 이동.
- 공지와 활동소식은 분류·날짜·제목을 빠르게 읽도록 배치한다. 모든 행을 별도 카드로 만들지 않는다.
- 결과가 있으면 상단 초기화, 0건이면 empty state 내부 초기화만 제공한다. 검색어·분류·페이지를 상세 복귀 URL에 유지한다.
- `/transparency`: 분류·기간 GET 필터 뒤에 문서명·기준 기간·문서일·게시일·형식·크기·PDF 열기를 비교 가능한 행으로 제공한다.
- 날짜 표시 `YYYY.MM.DD`와 machine-readable 값은 별개로 유지한다. 파일이 없을 때 가짜 링크를 만들지 않는다.

## 상세

소식·프로그램·갤러리는 공통 제목 영역을 사용한다. 목록 복귀, 분류, 제목, 선택 요약, 날짜, 본문 또는 사진, 첨부, 목록 복귀 순이다. 갤러리는 원본 사진 비율을 지킨다. 텍스트는 최대 읽기 폭을 제한한다. 개발용 콘텐츠 표시는 유지한다. 제목과 같은 요약은 중복하지 않는다. canonical에는 검색 복귀값을 넣지 않는다.

## 함께하기

- `/support`: 후원과 자원봉사를 두 개의 선택 영역으로 구분한다. 안내 보기와 문의 접수는 서로 다른 행동이다.
- `/support/donation`, `/support/volunteer`: 확인 안내와 세로 절차, 보조 문의 영역을 제공한다. 테스트 계좌 경고와 실제 CMS 문구를 유지한다.
- `/support/contact`: 온라인 문의를 주 열, 전화·주소·방문·공식 소셜을 보조 열로 제공한다. 필수 의미, 전화/이메일 조건, 개인정보 안내, 동의, 오류 연결과 disabled 상태를 유지한다.

## 관리자

공통 셸·헤더·필터·상태·내용 구획으로 모든 콘텐츠/운영 모듈을 연결한다. 대시보드는 업무 인덱스이며 가짜 통계는 없다. 상세의 수동 조작 기능은 기존 권한에 따라 렌더링한다. 수정 이력은 summary로 펼치며 확인 checkbox와 위험 행동은 접지 않는다. 표 overflow는 표 컨테이너 안에서 처리하고 페이지 전체의 가로 overflow는 허용하지 않는다.

## 검증

대표 화면에서 시각 방향을 먼저 확인하고 각 유형의 나머지 화면으로 확장한다. 0건/오류/긴 제목/이미지 없음/사진 실패/키보드/감소 모션/모바일을 검증 범위에 포함한다. 실행하지 않은 실제 화면 검증은 미검증으로 보고한다. 과거 QA PASS를 새 화면의 PASS로 전용하지 않는다.
