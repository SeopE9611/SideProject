# 콘텐츠 운영 및 공개 기준

## 기본 원칙

거주인의 존엄성과 사생활을 홍보보다 우선한다. 공개 필요성이 명확한 최소 정보만 게시하고, 정확성·공개 권한·개인정보와 민감정보·접근성을 확인한 뒤 승인한다. 내부 문서 원본을 공개자료로 사용하지 않으며 오래된 정보는 정기적으로 검토한다.

## 콘텐츠 상태

### `official`

- 운영 담당자가 확인하여 실제 공개할 수 있는 공식 콘텐츠다.
- 출처, 검토일, 공개 범위와 승인 상태를 기록한다.

### `fixture`

- 레이아웃, 콘텐츠 밀도, 반응형과 기능 검증용 테스트 콘텐츠다.
- 실제 기관 정보로 사용하지 않고 운영 공개 전에 교체한다.
- 코드에서는 중앙 fixture 모듈에서만 관리한다.

### `demo`

- 기능 시연이나 테스트 자동화를 위해 정해진 시나리오에서 사용하는 콘텐츠다.
- 공개 목록에서는 기본 제외하고 운영 데이터와 분리한다.

`fixture`는 실제 화면의 다양한 콘텐츠 상태와 레이아웃을 설계하기 위한 입력이고, `demo`는 반복 가능한 시연·자동화 시나리오를 위한 입력이다. 둘 다 `official`로 자동 전환하지 않으며 운영 공개할 수 없다.

## 공개 범위

운영자 승인 후 공식 시설 소개, 승인된 주소·연락처, 프로그램·후원·자원봉사 안내, 개인정보가 제거된 활동 소식과 승인된 운영자료를 공개할 수 있다. 얼굴·이름·음성·인터뷰·사례와 개인을 추정할 수 있는 위치·일정은 별도 동의와 검수가 필요하다.

다음은 공개하지 않는다.

- 주민등록번호, 장애·진단·의료·복약·상담·개별 지원 기록
- 보호자 정보, 가족관계, 개인 연락처와 직원 개인 연락처
- 비공개 후원자 정보, 내부 인사·사건·회의·행정 자료
- 미승인 예산·결산, 원본 신청서, 계정·인증정보

여러 공개 정보의 조합으로 개인을 식별할 수 있는지도 확인한다. 공개 여부가 불분명하면 먼저 게시하지 않고 운영자와 필요한 전문가의 확인을 받는다.

## 사진·영상·음성

- 촬영과 공개 동의, 채널, 게시 기간, 철회 절차를 확인한다.
- 배경의 문서, 이름표, 주소, 차량번호와 파일 메타데이터를 검수한다.
- 거주인을 홍보 수단으로 다루거나 외모·장애를 불필요하게 묘사하지 않는다.
- 원본과 공개용 파일을 분리하고 승인된 공개용 파일만 사용한다.

## placeholder 이미지

### 허용

- 중앙 fixture 데이터에 등록한 URL 이미지
- 프로젝트 내부 placeholder 이미지
- 비인물 시설·공간·활동 이미지
- 비율과 크롭 검증을 위한 다양한 가로·세로 이미지

### 금지

- 실제 거주인으로 오해할 수 있는 인물 사진과 출처 불명 이미지
- 실제 샬롬의 집 사진처럼 설명하는 행위
- 컴포넌트 내부의 임의 URL 직접 하드코딩
- 여러 파일에 같은 placeholder URL을 중복 작성하는 행위

향후 구현 단계의 모든 테스트 데이터는 다음 중앙 fixture 모듈에서 관리한다. 이번 문서 작업에서는 해당 TypeScript 파일을 만들지 않는다.

```text
src/content/fixtures/
├─ home.fixture.ts
├─ news.fixture.ts
├─ life.fixture.ts
├─ support.fixture.ts
└─ transparency.fixture.ts
```

## 분야별 승인 원칙

- 직원 이름·직책·업무 연락처는 공식 승인 범위만 공개하고 변경 시 갱신한다.
- 계좌, 예금주, 후원 방식과 세액공제 안내는 담당자 또는 전문가 확인 전 게시하지 않는다.
- 자원봉사 신청 정보는 최소화하고 신청서와 연락처를 공개 게시물에 노출하지 않는다.
- 투명성 자료는 승인된 최종본만 사용하며 제목, 기준 기간, 게시일, 수정일, 형식과 용량을 표시한다.
- 접근 가능한 문서를 우선하고 핵심 내용을 웹페이지에도 제공하는 방안을 검토한다.

## 작성·검수·공개 절차

```text
작성 → 개인정보·민감정보 확인 → 사실과 공개 권한 확인 → 접근성 확인
→ 승인 → 공개 → 정기 검토 → 수정·비공개·삭제
```

CMS 기능 구현 여부와 관계없이 공개 전 검수를 생략하지 않는다. 개인정보 노출 가능성이 있으면 우선 비공개한 뒤 확인한다. 최종 승인자, 동의 양식과 보관 기간, 검수 주기, 파일 정책, 역할·권한, 긴급 비공개와 검색엔진 삭제 절차는 운영자 확인이 필요하다.
