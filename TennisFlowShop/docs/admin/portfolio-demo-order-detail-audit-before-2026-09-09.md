## 주문 유형별 검사 결과

- 일반 상품: 5건 렌더링 성공. 수량·단가·상품 소계 산술은 일치했으나, 청구되지 않은 장착비가 노출됐다.
- 교체서비스 연결: 연결 여부, 스트링, 게이지·색상, 장력, 수령 방식, 요청사항, 신청 상태가 요약에 노출됐다. 연결 상세 이동은 로딩 실패했다.
- 방문 수령: 방문 수령 Badge와 최종 금액 22,000원은 확인했다. 배송비 0원은 명시되지 않았고 상태 문맥이 배송 용어와 혼재했다.
- 배송: 택배 Badge는 일관되게 표시됐다. 배송비가 명시되지 않았고 미완성 배송정보가 등록 완료로 표시됐다.
- 결제 상태별: 결제대기와 결제완료 주문을 확인했다. 실제 데이터에는 NICEPAY가 없었다.
- 취소/완료 계열: 취소 요청 1건과 방문 수령 완료 1건을 확인했다. 완료·취소 처리 UI 정책 문제가 있었다.
- Demo Interaction 주문: 최근 생성 주문 1건을 확인했다. 연결 신청서와 금액 산술은 존재했으나 연결 상세 로딩과 연락처 표시 형식 문제가 있었다.

## Console / Network

- Console: 주문 취소 Dialog에서 접근성 경고 1종을 재현했다.
- Console: 점검한 주문 상세 자체에서는 React 예외·hydration 오류·site-origin `console.error`를 관찰하지 못했다.
- Network: 브라우저 제어 환경에서 요청 목록의 method/status 원문을 직접 추출할 수 없어 4xx/5xx 수치는 확정하지 않았다. 화면상 연결 신청서와 배송 수정 조회 실패는 반복 재현했다.
- 자동 polling으로 보이는 반복 요청은 실제 페이지 오류로 분류하지 않았다.

## 레이아웃 / UX

- 실측 1348×936에서 불필요한 horizontal scroll, 주문번호 overflow, 버튼 잘림은 관찰하지 못했다.
- 상태·결제·배송·연결 카드의 정보 구조는 유지됐으나, 금액 구성과 상태 문맥의 우선순위가 불명확했다.
- 요청한 정확한 1440px가 아닌 1348px 브라우저였으므로 1440px 전용 판정은 제한 사항으로 남긴다.
